# 景点规划引擎规则梳理

> 基于 `backend/app/planner.py`（1165 行）逐行梳理，更新于 2026-08-28。
> 主路径为**规则化地理规划**（`_geo_plan`，source=`geo`），AI 生成作为兜底路径。

## 0. 意图参数检测（`intent.py`）

从对话中提取结构化规划参数，AI 优先 + 规则兜底，最新消息强信号覆盖 AI。

| 输入参数 | 是否必须 | 默认 | 说明 |
|---|---|---|---|
| 目的地 `destination` | **必须有** | — | 全国/省/市/区县/具体地点；缺失时回复追问「想去哪儿」 |
| 出发点 `origin` | 非必须 | 空 | 仅「从X出发/从X来」句式提取 |
| 人数 `travelers` | 非必须 | 1 人 | 支持「两个人/带爸妈/我们三个/3大1小」 |
| 返回点 `return_point` | 非必须 | 空 | 仅「回到X/返回X」句式提取 |
| 出行时间跨度 `days` | 非必须 | 2~3 天 | 年/月/日归一化（见下） |
| 出行方式 `traffic_mode` | 非必须 | 公共交通 | 自驾/公共交通/骑行/步行/混合 |

**时间跨度归一化与收束**（`_normalize_days`，支持中文数字）：
- `N天/N天N夜` → N 天；`N周` → N×7；`N个月` → N×30；`N年` → N×365
- 收束到 `MAX_DAYS=15`（「玩一个月」→15、「玩两年」→15），避免规划点不足或过于庞杂
- `build_plan` 再按**实际可分配的区域/市数**收束一次（北京枚举 21 区域 → 3 天不砍）

## 0. 主流程（`build_plan`）

```
定位城市中心(geocode)
  → 检索辅助 POI 池(美食/购物/夜生活) + 应用排除规则
  → 查询天气
  → 行政分级枚举景点(区/县→市→省) ← 构成主线
  → _geo_plan 规则化地理规划(聚类→圈层分配→逐日构建)
  → 天数不足用规则补齐(_ensure_days)
  → 非 geo 路径跨天地域去重(_enforce_region_distinct)
  → 汇总(预算/文案/时间轴)
```

两条引擎路径：
- **主路径 `_geo_plan`**：景点行政枚举 + 聚类 + 圈层分配，辅助点只做就近点缀
- **兜底路径 `_rule_plan`**：老规则引擎（按类别/评分/距离逐日排），用于 AI 失败、补天数、无地理数据时

---

## 1. 行政分级枚举景点（`_enumerate_scoped_attractions`）

按行政编码三级枚举，构成景点主线：

| 级别 | 编码 | 检索关键词 |
|---|---|---|
| 区/县 | `adcode` | 景区 / 5A / 博物馆 / 公园 / 古镇 |
| 市 | `adcode[:4]+"00"` | 景区 / 5A / 博物馆 / 公园 / 古镇 |
| 省 | `adcode[:2]+"0000"` | 5A / 旅游度假区 / 古镇 / 国家级风景名胜区 |

**关键规则：**
- **防跨城污染**：按高德返回的 `cityname` 过滤掉不属于目标城市的 POI（如佛山枚举不混入广州塔）
- **距离约束**：距城市中心 ≤ 150km（`SCOPE_MAX_RANGE`）
- **关闭过滤**：名称含「暂停开放/暂停营业/闭园/维修中/建设中」等标记剔除
- **子场馆剔除**：`故宫博物院-中和殿` 这类以短名开头 + `-` 连接的子场馆去掉
- 合并三级结果去重（名称+坐标），按评分降序

---

## 2. 必去地标注入（`_inject_must_visit_attrs`）

解决「行政枚举漏掉长城/颐和园等顶级地标」问题：
- **数据源**：后台 `must_visit` 表优先（M6 可管理），表无数据回退 `data/must_visit.py` 知识库
- 只取 `category=景点` 条目
- 同名已在候选池 → 补打 `must_visit/hot` 权重与评分
- 未命中 → `resolve_poi` 解析真实坐标后**置前**，标记 `hot`（放宽距离约束至 100km）

**评分加成**（`_rank`）：`rating + 0.3(must_visit) / +0.1(hot)`，仅用于排序分组，不改展示评分

---

## 3. 景点聚类（`_cluster_attractions`）

把景点按地理邻近聚成「区域」（同一天）：
- **距离上限**：12km（`CLUSTER_MAX_DIST`）
- **种子策略**：高分景点优先作种子（`_rank` 排序），保证每区域至少一个优质点位
- 动态更新区域中心（均值）
- **稀疏簇合并**：景点 < 2 的簇并入最近邻簇（12km 内），避免「空壳日」

---

## 4. 区域分配到天（`_assign_areas_to_days`）

**核心策略 = 由近及远、按圈层轮流**：

1. **拆分**：大区域拆成 ≤3 景点的均衡子区域（`_greedy_group`，高分锚点 + 就近高分邻居，同分取离市中心近的）
2. **距离分层**（`_dist_tier`）：

| tier | 距离 | zone |
|---|---|---|
| 0 | ≤10km | 市区 |
| 1 | ≤25km | 近郊 |
| 2 | ≤60km | 远郊 |
| 3 | >60km | 远郊（截断为 zone2） |

3. **天序**：每天覆盖一个圈层且不重复，`i` 轮按 zone 0→1→2 轮流取第 `i` 个候选。3 天北京 = 故宫天安门(市区) + 颐和园(近郊) + 八达岭长城(远郊)
4. **远郊门槛**：评分 < 4.5 的远郊区域本轮跳过，名额让给近圈层
5. **圈层内排序**：城市名片(世界遗产/国家级) → 地标加权评分 → 距离近
6. **不足补足**：从剩余区域按 (圈层, 评分, 距离) 补足到天数

### 省级目的地：按市分隔（`_province_areas`）

当目的地是**省/自治区**（`_is_province`：level 含"省/自治区"且非直辖市 adcode 110000/120000/310000/500000）时：
1. 全省景点按 `cityname` 分组（每组 = 一个市）
2. 每个市内就近聚类成区域（12km）
3. 城市按（含城市名片数 → 评分 → 距省中心距离）排序
4. 每天分配一个市的区域；天数多于市数时回到高分市补充

> 实测「山东 4 天」= 泰山(泰安) / 曲阜三孔(济宁) / 周村古商城(淄博) / 泉城欧乐堡(德州)。
> 省级枚举**不过滤城市**（保留省内各市），改按 `province` 过滤防跨省污染。

## 4.5 住宿锚点（`DayPlan.hotel`）

- 存在时间跨度时，每天就近选一个住宿点（`amap.search_hotel_near`，酒店类型，真实/mock 双模式）
- **住宿点 = 次日出发起点**：`_reorder_day` 的 day_start 用前晚酒店坐标（首日=市中心），就近重排
- 前端 DayCard 展示「当晚住宿」

---

## 5. 单日构建（`_build_geo_day`）

每天 = **2-3 个景点主线 + 1 个就近辅助**：

- **景点数**：按节奏 `轻松3→2景点 / 适中4→3 / 暴走5→3`；人群修正（亲子/老人→轻松、朋友→暴走）
- **补足**：区域不足时，仅补「距区域中心 ≤10km」的未用景点（保持紧凑，杜绝跨区跳点）
- **同地标词去重**（`_dedup_landmark_day`）：一天内命中同一地标特征词（如「长城」）只留评分最高，避免「长城三连」
- **就近辅助**（`_pick_auxiliary`）：美食/购物/夜生活 1 个，15km 内，优先级美食>夜生活>购物；过滤酒店名、美食名称护栏（植物园/公园等不算餐厅）；远处区域就地检索（`_local_aux`，避免跨区污染）
- 辅助点时段：夜生活→晚上、其余→中午

**当日点位重排**（`_reorder_day`）：
- 夜生活固定放末尾（晚间语义）
- 首停靠点 = 离市中心最近的景点（近似从酒店出发）
- 其余按最近邻串联，起点=市中心

**时间轴校验**（`_apply_timeline`）：按序累加「站间交通 + 停留时长」，落点必须在每日窗口内；冲突自动顺延，超窗口截断

---

## 6. 跨天区域不重复

- **geo 主路径**：按子区域天然不重复（每区域只分配一天），无需额外处理
- **非 geo 路径**（`_enforce_region_distinct`）：
  - 主区域（区县名，`_region_of`）重复 → 切换未占用区域重建当天
  - 同天混入他区点位 → 替换为主区域未用点位（同品类优先）
  - 点位不足的小城市自动跳过，不破坏原行程

---

## 7. 辅助/兜底规则

| 规则 | 说明 |
|---|---|
| 排除点位 | `exclude_poi` 名称过滤（景点与辅助池均应用） |
| 必去点位 | `must_include_poi` 解析后置前注入主线 |
| 候选不足 | 景点 < 6 时并入辅助池中的景点兜底 |
| 兜底引擎 | `_rule_plan`：按 上午景点→中午美食→下午景点→购物→晚上夜景 骨架逐日排 |
| 极端兜底 | 无任何点位 → `_emergency_plan` 生成最简单一天 |
| 天数补齐 | `_ensure_days`：AI/地理产出不足时用规则引擎补足 |

---

## 8. 预算与节奏参数

| 参数 | 取值 |
|---|---|
| 预算档位（每天人均） | 经济30/150/30、适中80/400/60、舒适150/800/120、奢华300/1500/200（餐饮/住宿/交通） |
| 节奏点位 | 轻松3 / 适中4 / 暴走5 |
| 人群节奏 | 亲子/老人→轻松、单人/情侣/家庭→适中、朋友→暴走 |
| 单日预算构成 | 餐饮(按餐数≥2) + 门票(景点价) + 交通 + 住宿 |

## 9. 可调点速查（便于后续优化）

| 可调项 | 位置 | 当前值 |
|---|---|---|
| 聚类距离上限 | `CLUSTER_MAX_DIST` | 12km |
| 省内距离上限 | `SCOPE_MAX_RANGE` | 150km |
| 圈层切分 | `_dist_tier` | 10/25/60km |
| 远郊评分门槛 | `_assign_areas_to_days` | ≥4.5 |
| 区域补点距离 | `_build_geo_day` | ≤10km |
| 辅助点距离 | `_pick_auxiliary` | ≤15km |
| 同地标去重 | `LANDMARK_WORDS` 特征词表 | 全国知名地标词 |
| 地标加成 | `_rank` | must_visit +0.3 / hot +0.1 |
| 每区域景点数 | `_greedy_group max_n` | 3 |
| 天数上限 | `intent.MAX_DAYS` | 15 天 |
| 周/月/年折算 | `intent.DAYS_PER_*` | 7 / 30 / 365 |
| 住宿检索半径 | `amap.search_hotel_near` | 12km |
