# AI旅行规划产品 - 能力升级规划

## 📊 项目现状分析

### 当前规模
- **后端**：36,295行代码，135个API接口，22个数据库表
- **前端**：8,332行代码，19个页面，3个组件
- **Skill模块**：3个（意图识别、规则引擎、行程规划）
- **管理后台**：15个管理面板

### 核心能力
✅ 行程规划（规则引擎 + LLM辅助）
✅ 对话式规划（多轮对话）
✅ 探索功能（地图周边景点）
✅ 用户系统（JWT + bcrypt）
✅ RAG知识库（景点人文介绍）
✅ 地图服务（高德/腾讯双Provider + 熔断）
✅ 主要景点库（183个）
✅ POI层级数据（主景点/子景点/周边）
✅ 历史人物关联（12个人物，53个关联地点）

### 主要瓶颈
❌ 第三方地图API额度限制和数据覆盖不全
❌ LLM意图识别不稳定，受历史对话干扰
❌ 规划质量有待提升（主子POI重复、必去景点缺失）
❌ 前端组件化程度低（只有3个组件）
❌ 缺少用户生态（评价、分享、社区）
❌ 缺少商业化能力

## 🚀 能力升级方向（7大维度）

### 维度一：AI能力升级 ⭐⭐⭐⭐⭐

#### 1.1 多模型路由
- **现状**：单一模型（qwen2:7b）处理所有任务
- **升级**：根据任务类型选择最合适的模型
  - 意图识别 → 轻量模型（3B），快速响应
  - 行程规划 → 中等模型（7B），平衡质量和速度
  - 人文介绍 → 大模型（14B/云端API），质量优先
  - 代码/数据处理 → 专用模型
- **预期效果**：响应速度提升30%，成本降低40%

#### 1.2 意图识别优化
- **现状**：受历史对话干扰大，参数识别不准确
- **升级**：
  - 上下文窗口管理（只保留最近N轮 + 关键信息摘要）
  - 实体识别增强（地名、时间、人数、预算等）
  - 歧义消解（同名地点确认、多义词处理）
  - 槽位填充机制（参数不足时主动追问）
- **预期效果**：意图识别准确率从70%提升到90%+

#### 1.3 规划质量优化
- **现状**：规则引擎为主，LLM辅助不足
- **升级**：
  - LLM生成候选方案 → 规则引擎验证和优化
  - 多方案生成（3-5个方案供用户选择）
  - 方案对比和推荐理由
  - 用户反馈学习（根据用户调整优化后续规划）
- **预期效果**：规划满意度提升50%

#### 1.4 多轮对话优化
- **现状**：对话状态管理简单
- **升级**：
  - 对话状态机（规划中/调整中/确认中/完成）
  - 上下文记忆（记住用户偏好和历史选择）
  - 主动引导（参数不足时主动提问）
  - 自然语言调整（"把第二天改成休闲一点"）
- **预期效果**：对话完成率提升40%

#### 1.5 语音交互
- **现状**：有基础语音介绍代码
- **升级**：
  - 语音输入（ASR）
  - 语音输出（TTS，景点介绍）
  - 语音导航（实时语音指引）
  - 多语言支持
- **预期效果**：使用场景扩展（驾车、步行等）

### 维度二：数据能力升级 ⭐⭐⭐⭐⭐

#### 2.1 自建景点数据库
- **现状**：依赖第三方地图API，数据覆盖不全
- **升级**：
  - 爬取/整合多源数据（携程、马蜂窝、大众点评、维基百科等）
  - 景点富化（开放时间、门票、评分、图片、标签、最佳季节）
  - 数据审核流程（人工审核 + 自动校验）
  - 数据更新策略（定期更新 + 实时反馈）
- **预期效果**：景点覆盖率从60%提升到95%+

#### 2.2 POI数据富化
- **现状**：POI数据基础信息不全
- **升级**：
  - 开放时间（精确到小时，包含节假日特殊安排）
  - 门票价格（成人/儿童/老人/学生，优惠政策）
  - 游玩时长（建议时长，最短/最长）
  - 评分和评论数（多平台综合）
  - 图片和视频
  - 标签和分类（亲子/情侣/摄影/历史/自然等）
  - 最佳游览时间（季节/时段）
  - 避坑提示
- **预期效果**：规划精准度提升60%

#### 2.3 行政区域数据完善
- **现状**：有3238个行政区域，但关联关系可能不全
- **升级**：
  - 完善省-市-区县-乡镇四级关联
  - 城市中心坐标和边界
  - 城市标签（旅游城市/历史名城/美食之都等）
  - 最佳旅游季节
  - 城市简介和特色
- **预期效果**：地理枚举准确率提升到99%

#### 2.4 用户行为数据
- **现状**：有基础的会话和行程记录
- **升级**：
  - 用户行为埋点（浏览/点击/收藏/分享/调整）
  - 用户画像构建（偏好/预算/节奏/兴趣）
  - 行程完成度跟踪
  - 用户反馈收集（评分/评价/建议）
  - A/B测试框架
- **预期效果**：个性化推荐能力，用户留存提升30%

#### 2.5 实时数据接入
- **现状**：天气有基础接入
- **升级**：
  - 实时交通（拥堵/事故/管制）
  - 实时天气（降水/温度/风力/空气质量）
  - 景点实时状态（开放/关闭/拥挤度/排队时间）
  - 票务实时信息（余票/价格波动）
  - 节假日和活动信息
- **预期效果**：规划实用性提升70%

### 维度三：规划引擎升级 ⭐⭐⭐⭐

#### 3.1 多策略规划
- **现状**：单一规划策略
- **升级**：
  - 经典打卡（必去景点全覆盖）
  - 深度体验（小众景点+当地生活）
  - 休闲度假（慢节奏+舒适住宿）
  - 亲子友好（儿童景点+安全考虑）
  - 情侣浪漫（浪漫景点+私密体验）
  - 摄影之旅（最佳机位+黄金时间）
  - 美食之旅（特色餐厅+当地小吃）
  - 历史文化（博物馆+古迹+讲解）
- **预期效果**：满足不同用户需求，满意度提升50%

#### 3.2 多目标优化
- **现状**：主要考虑地理位置
- **升级**：
  - 时间优化（最少通勤时间）
  - 距离优化（最短路径）
  - 预算优化（控制总花费）
  - 兴趣匹配（最大化用户兴趣点）
  - 体力优化（根据用户体力调整强度）
  - 多目标权衡（帕累托最优）
- **预期效果**：规划合理性提升40%

#### 3.3 动态调整
- **现状**：规划生成后固定
- **升级**：
  - 实时天气调整（下雨时推荐室内景点）
  - 实时交通调整（拥堵时调整顺序或交通方式）
  - 用户位置调整（根据用户实时位置推荐下一步）
  - 景点状态调整（景点关闭时自动替换）
  - 时间弹性调整（用户提前/延后时自动适配）
- **预期效果**：规划实用性提升80%

#### 3.4 大景区内部规划
- **现状**：大景区内子景点处理不好
- **升级**：
  - 景区内部路线规划（入口→核心景点→出口）
  - 景区内交通（观光车/游船/缆车）
  - 景区内时间分配（根据景点大小和重要性）
  - 景区内餐饮和休息点
  - 景区内最佳游览顺序
- **预期效果**：大景区体验提升60%

#### 3.5 跨城/跨省规划
- **现状**：主要支持单城市规划
- **升级**：
  - 多城市路线优化（城市间交通方式和时间）
  - 城市间住宿安排
  - 省际大环线规划（如云南大环线、川西大环线）
  - 主题路线（如丝绸之路、长征路线、唐诗之路）
  - 时间跨度大时的月度/季度规划
- **预期效果**：使用场景扩展，客单价提升50%
