# 行程规划引擎完整规则体系

> 文档版本：v2.0（整合版）  
> 更新时间：2026-08-29  
> 适用范围：行程规划引擎的完整规则体系，包括9阶段流程、核心规则（无上限参数收束、人群影响、出行方式影响及灵活机制）、各阶段详细规则

---

## 1. 文档概述

本文档是行程规划引擎的完整规则体系，整合了《行程规划引擎完整流程与规则体系》和《规划引擎核心规则体系设计》两个文档，包含以下核心内容：

1. **9阶段完整流程**：从用户输入到最终输出的完整规划流程，每个阶段的输入、输出、核心职责、详细规则。
2. **无上限参数的兜底和收束**：时间、人数、预算这些参数可以无上限，需要划定最小值作为兜底，同时当值极大时需要策略做好收束，规则要闭环。
3. **人群参数对出行规划的影响点**：亲子、老人、情侣、单人、家庭、朋友等不同人群对规划的具体影响是什么，影响比例是多少，会不会影响主要景点规划。
4. **出行方式的影响规则**：公共交通（高铁、大巴、公交、地铁、打车、共享）和自驾对规划的影响，景点与景点之间的通行方式选择。
5. **出行方式影响的灵活机制**：出行方式对规划的影响不应该是硬性约束，而应该是灵活的、可调节的，根据场景判断影响强度（强/中/弱），可以影响也可以不影响。
6. **出行方式规划进行程的程度分级**：出行方式要不要规划进行程、规划到什么程度，也是一个影响很大的点，根据场景判断规划程度（详细规划/简要规划/不规划）。

**核心原则**：
- 规则要闭环，既要兜底（最小值），也要收束（最大值），同时要明确影响点和影响比例。
- 出行方式影响要灵活，根据场景动态调整影响强度和规划程度。
- 每个阶段职责单一，可独立优化、可独立验证。

## 2. 规划流程总览

### 2.1 九阶段流程

```
用户输入
    ↓
【阶段1】参数识别（LLM解析）
    ↓ 规划参数（destination, days, travelers, group_type, budget_level, style, pace, traffic_mode...）
【阶段2】景点检索与筛选
    1. 目的地同名地点处理
    2. 行政分级枚举
    3. POI检索
    4. 按照人群筛选
    ↓ 候选景点池（筛选后的景点列表）
【阶段3】景点聚类与分组
    1. 主/子POI的识别规划
    2. 景点的分组
    3. 按照地理距离的规划
    ↓ 景点聚类（多个景点组，每组包含地理位置相近的景点）
【阶段4】按天分配与切分
    - 基于旅行体验曲线的分配
    - 基于体力曲线的分配
    - 基于景点热度的分配
    - 基于住宿区域的分配
    ↓ 每日景点（每天分配的景点列表）
【阶段5】每日排序与时间线
    - 基于人流高峰的排序
    - 基于光照和拍照的排序
    - 基于用餐的排序
    - 基于开放时间的精确排序
    - 基于交通时间的精确排序
    - 基于主/子POI的排序
    ↓ 时间线行程（每天内景点顺序+时间段）
【阶段6】辅助点位与通行建议（含检视与补充）
    1. 辅助点位推荐
    2. 通行建议
    3. 规划完成后检视整体行程
    4. 不符合要求从候选景点池没入选和辅助点位中挑选穿插进去
    5. 后续暂不更改
    ↓ 完整行程（景点+美食+购物+夜生活+通行建议）
【阶段7】预算计算与优化
    ↓ 带预算行程（餐饮+住宿+交通+门票+总预算）
【阶段8】LLM优化与文案生成
    ↓ 优化后行程（智能优化+人文介绍+出发语+每日灵感+回复文案）
【阶段9】验证与输出
    ↓
最终行程输出
```

### 2.2 各阶段核心职责

| 阶段 | 名称 | 核心职责 | 输入 | 输出 |
|------|------|----------|------|------|
| 1 | 参数识别 | LLM解析用户输入，提取规划参数 | 用户对话 | 规划参数对象 |
| 2 | 景点检索与筛选 | 同名处理→行政枚举→POI检索→人群筛选 | 规划参数 | 候选景点池 |
| 3 | 景点聚类与分组 | 主/子POI识别→景点分组→地理距离规划 | 候选景点池 | 景点聚类 |
| 4 | 按天分配与切分 | 按体验曲线/体力曲线/热度/住宿区域分配 | 景点聚类 | 每日景点 |
| 5 | 每日排序与时间线 | 按人流高峰/光照/用餐/开放时间/交通时间排序 | 每日景点 | 时间线行程 |
| 6 | 辅助点位与通行建议 | 辅助点位+通行建议+检视与补充 | 时间线行程 | 完整行程 |
| 7 | 预算计算与优化 | 计算各项预算，优化调整 | 完整行程 | 带预算行程 |
| 8 | LLM优化与文案生成 | LLM智能优化，生成文案和人文介绍 | 带预算行程 | 优化后行程 |
| 9 | 验证与输出 | 验证行程合理性，格式化输出 | 优化后行程 | 最终行程 |

## 3. 核心规则体系

### 3.1 无上限参数的兜底和收束规则

#### 3.1.1 设计原则

无上限参数（时间、人数、预算）需要遵循以下设计原则：

1. **兜底原则**：划定最小值，确保参数不会过小导致规划无法进行
2. **收束原则**：划定最大值或收束策略，确保参数不会过大导致规划过于庞杂
3. **闭环原则**：从最小值到最大值形成完整的规则体系，每个区间都有明确的处理策略
4. **渐进原则**：参数值的变化对规划的影响应该是渐进的，而不是突变的

---

#### 3.1.2 时间参数（days）的兜底和收束

**参数定义**：
- **参数名**：days
- **含义**：出行时间跨度（天）
- **原始输入**：用户可能输入任意天数，甚至以周/月/年为单位

**兜底规则（最小值）**：
- **最小天数**：1天
- **兜底逻辑**：
  - 如果用户输入 < 1天，默认设置为1天
  - 1天行程：单日游，不需要住宿，不需要考虑跨天交通

**收束规则（最大值）**：
- **最大天数**：15天（硬上限）
- **收束逻辑**：
  - 如果用户输入 > 15天，收束为15天
  - 超过15天的行程需要特殊处理（见大时间跨度规划）

**分区间处理策略**：

| 天数区间 | 规划策略 | 景点数量 | 住宿安排 | 聚类方式 |
|----------|----------|----------|----------|----------|
| **1天** | 单日游 | 3-5个景点 | 无住宿 | 1个聚类 |
| **2-3天** | 短途游 | 每天3-5个，总计6-15个 | 1-2晚住宿 | 2-3个聚类 |
| **4-7天** | 中途游 | 每天3-5个，总计12-35个 | 3-6晚住宿 | 4-7个聚类，可能跨城市 |
| **8-15天** | 长途游 | 每天2-4个，总计16-60个 | 7-14晚住宿 | 8-15个聚类，跨城市/跨省 |
| **>15天** | 收束为15天 | 同上 | 同上 | 同上 |

**时间跨度收束的闭环规则**：
```
用户输入天数
    ↓
是否 < 1天？ → 是 → 设置为1天（兜底）
    ↓ 否
是否 > 15天？ → 是 → 设置为15天（收束）
    ↓ 否
是否以周/月/年为单位？ → 是 → 转换为天数（周×7，月×30，年×365）
    ↓ 否
是否超过目的地可支撑的区域数？ → 是 → 收束为可支撑区域数
    ↓ 否
使用用户输入天数
```

**大时间跨度（月/年）的特殊处理**：

| 时间单位 | 处理策略 | 规划粒度 |
|----------|----------|----------|
| **1个月** | 规划当前省或临近省，按周拆分 | 每周2-3个城市，每个城市2-3天 |
| **2个月** | 安排2个省，按月拆分 | 每个省1个月，按周拆分 |
| **3-6个月** | 安排3-6个省，按月拆分 | 每个省1个月，按周拆分 |
| **>6个月** | 收束为6个月，安排6个省 | 每个省1个月，按周拆分 |
| **1年** | 按省规划，哪个月是这个省的最佳出行时间就安排在哪个月 | 每月1个省，按最佳季节分配 |

#### 3.1.3 人数参数（travelers）的兜底和收束

**参数定义**：
- **参数名**：travelers
- **含义**：出行人数
- **原始输入**：用户可能输入任意人数

**兜底规则（最小值）**：
- **最小人数**：1人
- **兜底逻辑**：
  - 如果用户输入 < 1人，默认设置为1人
  - 1人出行：单人游，住宿按1间房计算，餐饮按1人计算

**收束规则（最大值）**：
- **最大人数**：99人（硬上限）
- **收束逻辑**：
  - 如果用户输入 > 99人，收束为99人
  - 超过20人的团体需要特殊处理

**分区间处理策略**：

| 人数区间 | 规划策略 | 住宿安排 | 餐饮安排 | 景点选择 |
|----------|----------|----------|----------|----------|
| **1人** | 单人游 | 1间单人间/青旅 | 单人餐 | 可以更小众、更个性化 |
| **2人** | 双人游 | 1间标准间 | 双人餐 | 可以更浪漫、更精致 |
| **3-4人** | 小团体 | 1-2间房 | 小桌餐 | 综合考虑，经典景点为主 |
| **5-10人** | 中团体 | 3-5间房 | 大桌餐/分餐 | 需要预约团体票，经典景点为主 |
| **11-20人** | 大团体 | 6-10间房 | 团体餐 | 需要预约团体票，避免过于分散 |
| **>20人** | 超大团体 | 收束为20人处理 | 团体餐 | 需要特殊安排，避免过于分散 |

**人数对预算计算的影响**：
- **住宿**：1-2人1间房，3-4人2间房，以此类推（每2人1间房）
- **餐饮**：按实际人数计算，团体可能有折扣（10人以上9折，20人以上8折）
- **交通**：按实际人数计算，团体可能有团体票优惠

**人数收束的闭环规则**：
```
用户输入人数
    ↓
是否 < 1人？ → 是 → 设置为1人（兜底）
    ↓ 否
是否 > 99人？ → 是 → 设置为99人（收束）
    ↓ 否
用户是否明确指定group_type？ → 是 → 根据group_type推断默认人数（如未指定人数）
    ↓ 否
使用用户输入人数
```

#### 3.1.4 预算参数（budget_level）的兜底和收束

**参数定义**：
- **参数名**：budget_level
- **含义**：预算档位（经济/适中/舒适/奢华）
- **原始输入**：用户可能输入具体金额，也可能输入档位

**兜底规则（最小值）**：
- **最低档位**：经济
- **兜底逻辑**：
  - 如果用户输入低于经济档，默认设置为经济档
  - 经济档：餐饮30元/人/顿，住宿150元/间/晚，交通30元/人/天

**收束规则（最大值）**：
- **最高档位**：奢华
- **收束逻辑**：
  - 如果用户输入高于奢华档，收束为奢华档
  - 奢华档：餐饮300元/人/顿，住宿1500元/间/晚，交通200元/人/天

**分档位处理策略**：

| 预算档位 | 餐饮预算 | 住宿预算 | 交通预算 | 景点选择 | 推荐类型 |
|----------|----------|----------|----------|----------|----------|
| **经济** | 30元/人/顿 | 150元/间/晚 | 30元/人/天 | 免费/低价景点 | 青旅、小吃、公共交通 |
| **适中** | 80元/人/顿 | 400元/间/晚 | 60元/人/天 | 综合考虑 | 连锁酒店、特色餐厅、地铁 |
| **舒适** | 150元/人/顿 | 800元/间/晚 | 120元/人/天 | 高品质景点 | 精品酒店、高档餐厅、打车 |
| **奢华** | 300元/人/顿 | 1500元/间/晚 | 200元/人/天 | 顶级景点/VIP | 五星级酒店、米其林、专车 |

**预算表**（BUDGET_TABLE）：
```python
BUDGET_TABLE = {
    "经济": {"food": 30, "hotel": 150, "transport": 30},
    "适中": {"food": 80, "hotel": 400, "transport": 60},
    "舒适": {"food": 150, "hotel": 800, "transport": 120},
    "奢华": {"food": 300, "hotel": 1500, "transport": 200},
}
```

**具体金额到档位的映射**：

| 人均总预算（3天） | 映射档位 | 说明 |
|-------------------|----------|------|
| < 500元 | 经济 | 穷游 |
| 500-1500元 | 适中 | 普通游 |
| 1500-3000元 | 舒适 | 品质游 |
| > 3000元 | 奢华 | 豪华游 |

**预算收束的闭环规则**：
```
用户输入预算
    ↓
是具体金额还是档位？ → 具体金额 → 映射到档位
    ↓ 档位
是否低于经济档？ → 是 → 设置为经济档（兜底）
    ↓ 否
是否高于奢华档？ → 是 → 设置为奢华档（收束）
    ↓ 否
使用用户输入档位
```

### 3.2 人群参数对出行规划的影响点

#### 3.2.1 设计原则

人群参数（group_type）对规划的影响应该遵循以下原则：

1. **主要景点优先**：无论什么人群，目标城市的主要景点（名胜古迹、标志性景点）都应该优先规划，人群参数只影响辅助景点和行程安排
2. **影响比例明确**：人群参数对规划的影响应该有明确的比例，而不是完全替代主要景点
3. **影响点清晰**：人群参数应该影响明确的维度（景点选择、节奏、餐饮、住宿、交通），而不是模糊的"适合"
4. **渐进影响**：人群参数的影响应该是渐进的，而不是非此即彼

---

#### 3.2.2 人群参数的影响维度

人群参数影响以下6个维度，每个维度的影响比例不同：

| 影响维度 | 影响程度 | 说明 |
|----------|----------|------|
| **主要景点选择** | 0-10% | 主要景点基本不受影响，所有人群都应该去 |
| **辅助景点选择** | 30-50% | 辅助景点受人群影响较大，如亲子选游乐园，情侣选浪漫景点 |
| **节奏安排** | 20-30% | 亲子/老人节奏慢，朋友节奏快 |
| **餐饮推荐** | 30-50% | 亲子选亲子餐厅，情侣选浪漫餐厅 |
| **住宿推荐** | 20-30% | 亲子选亲子酒店，情侣选情侣酒店 |
| **交通方式** | 10-20% | 亲子/老人更倾向自驾或打车 |

**核心原则**：主要景点（名胜古迹、标志性景点）占行程的70-90%，人群相关的辅助景点占10-30%。

---

#### 3.2.3 各人群类型的详细影响

##### 单人游

**影响点**：
- **主要景点**：100%保留，所有主要景点都可以去
- **辅助景点**：可以选择更小众、更个性化的景点（如独立书店、小众咖啡馆、艺术展览）
- **节奏**：适中节奏，每天4个点位
- **餐饮**：可以选择单人友好的餐厅（如一人食、小吃、快餐）
- **住宿**：单人间、青旅、经济型酒店
- **交通**：公共交通为主，灵活自由

**影响比例**：
- 主要景点：90%
- 辅助景点（小众/个性化）：10%
- 节奏：适中
- 餐饮：单人友好
- 住宿：经济型

---

##### 情侣游

**影响点**：
- **主要景点**：90%保留，所有主要景点都应该去
- **辅助景点**：增加浪漫氛围的景点（如夜景、摩天轮、湖边散步、浪漫咖啡馆、情侣主题餐厅）
- **节奏**：适中节奏，每天4个点位，可以更悠闲
- **餐饮**：增加浪漫餐厅推荐（如烛光晚餐、景观餐厅、网红餐厅）
- **住宿**：情侣酒店、精品酒店、浪漫主题房
- **交通**：可以选择更浪漫的交通方式（如游船、马车、观光巴士）

**影响比例**：
- 主要景点：80%
- 辅助景点（浪漫/网红）：20%
- 节奏：适中偏慢
- 餐饮：浪漫餐厅占30%
- 住宿：精品/情侣酒店

**注意事项**：
- **关键问题**：浪漫景点不应该影响主要景点的规划，主要景点（如故宫、长城）仍然是核心
- 浪漫景点应该作为辅助，穿插在主要景点之间（如晚上去看夜景，下午去浪漫咖啡馆）
- 不要把所有时间都花在浪漫景点上，否则会错过目标城市的主要景点

**浪漫景点的穿插策略**：
- 上午：主要景点（如故宫）
- 下午：主要景点 + 浪漫咖啡馆（如景山公园看故宫全景 + 附近咖啡馆）
- 晚上：浪漫景点（如什刹海夜景、南锣鼓巷漫步）
- 这样既保证了主要景点，又增加了浪漫氛围

---

##### 亲子游

**影响点**：
- **主要景点**：80%保留，大部分主要景点都应该去，但需要考虑亲子友好性
  - **可以去的名胜古迹**：故宫（有儿童讲解）、长城（缆车上下）、颐和园（游船）、天坛（开阔）
  - **需要调整的名胜古迹**：过于陡峭的山路（如华山）、过于枯燥的博物馆（如纯文字展览）
- **辅助景点**：增加亲子友好景点（如游乐园、动物园、海洋馆、科技馆、儿童博物馆、亲子主题乐园）
- **节奏**：轻松节奏，每天3个点位，中午需要午休
- **餐饮**：亲子餐厅、儿童友好餐厅、有儿童餐的餐厅
- **住宿**：亲子酒店、家庭房、有儿童设施的酒店
- **交通**：自驾或打车为主，减少换乘，避免长时间步行

**影响比例**：
- 主要景点（亲子友好的名胜古迹）：60%
- 辅助景点（亲子/游乐园）：40%
- 节奏：轻松，中午午休
- 餐饮：亲子餐厅占40%
- 住宿：亲子酒店/家庭房

**注意事项**：
- **关键问题**：亲子游不是只去游乐园，目标城市的名胜古迹仍然是核心，但需要选择亲子友好的名胜古迹
- 例如去北京，亲子游仍然应该去故宫、长城、颐和园，但需要：
  - 故宫：租儿童讲解器，走中轴线，不要走太多偏殿
  - 长城：选择慕田峪（有缆车，人少），不要选择八达岭（人多，陡峭）
  - 颐和园：乘船游览，不要全程步行
- 同时增加1-2个亲子景点（如北京动物园、中国科技馆、欢乐谷）

**亲子友好的名胜古迹筛选标准**：
- 有儿童讲解或互动设施
- 有缆车/游船等代步工具
- 场地开阔，不会过于拥挤
- 有休息区和卫生间
- 不会过于陡峭或需要大量体力

##### 家庭游

**影响点**：
- **主要景点**：90%保留，所有主要景点都应该去，需要考虑全家友好性
- **辅助景点**：增加全家友好景点（如公园、文化景点、经典景点）
- **节奏**：适中节奏，每天4个点位
- **餐饮**：全家友好餐厅（如中餐、家常菜、有包间的餐厅）
- **住宿**：家庭房、套房、连通房
- **交通**：根据家庭构成选择，有老人小孩倾向自驾或打车

**影响比例**：
- 主要景点：85%
- 辅助景点（全家友好）：15%
- 节奏：适中
- 餐饮：全家友好
- 住宿：家庭房/套房

##### 朋友游

**影响点**：
- **主要景点**：80%保留，主要景点仍然要去，但可以更灵活
- **辅助景点**：增加网红打卡、夜生活、美食、购物景点
- **节奏**：暴走节奏，每天5个点位，可以更紧凑
- **餐饮**：网红餐厅、特色小吃、夜市、美食街
- **住宿**：青旅、经济型酒店、民宿（可以一起住）
- **交通**：公共交通为主，可以尝试当地特色交通

**影响比例**：
- 主要景点：70%
- 辅助景点（网红/夜生活/美食）：30%
- 节奏：暴走
- 餐饮：网红/特色占50%
- 住宿：经济型/青旅/民宿

---

##### 老人游

**影响点**：
- **主要景点**：95%保留，老人游的核心就是看名胜古迹，主要景点几乎全部保留
- **辅助景点**：增加平缓、文化类景点（如公园、寺庙、历史文化街区）
- **节奏**：轻松节奏，每天3个点位，需要更多休息时间
- **餐饮**：清淡、软烂、易消化的餐厅，避免辛辣刺激
- **住宿**：舒适型酒店、低楼层房间、有电梯、靠近医院
- **交通**：自驾或打车为主，减少步行和换乘，避免高峰期

**影响比例**：
- 主要景点（名胜古迹）：90%
- 辅助景点（平缓/文化）：10%
- 节奏：轻松，多休息
- 餐饮：清淡/易消化
- 住宿：舒适型/低楼层/有电梯

**注意事项**：
- **关键问题**：老人游不是只去活动量小的景点，目标城市的名胜古迹仍然是核心，甚至是首要目标
- 例如去北京，老人游仍然应该去故宫、长城、颐和园、天坛，但需要：
  - 故宫：租轮椅，走中轴线，多休息
  - 长城：选择慕田峪（有缆车，平缓），不要选择八达岭（人多，陡峭）
  - 颐和园：乘船游览，不要全程步行
  - 天坛：走中轴线，不要走太多偏殿
- 辅助景点可以选择平缓的公园（如北海公园、景山公园），但不要替代主要景点

**老人友好的名胜古迹筛选标准**：
- 有轮椅通道或无障碍设施
- 有缆车/游船等代步工具
- 场地开阔，不会过于拥挤
- 有休息区和卫生间
- 不会过于陡峭或需要大量体力
- 有遮阳避雨的地方

### 3.3 出行方式的影响规则

#### 3.3.1 大交通方式的影响

**大交通方式分类**：

| 大交通方式 | 适用场景 | 优点 | 缺点 |
|------------|----------|------|------|
| **高铁** | 中短途（1-4小时），城市间 | 准时、舒适、快捷 | 费用较高，需要提前订票 |
| **飞机** | 长途（>4小时），跨省/跨国 | 快捷 | 费用高，受天气影响，需要提前到机场 |
| **大巴** | 中短途，高铁不方便的地方 | 费用低，班次多 | 慢，不舒适，受交通影响 |
| **自驾** | 中短途，灵活自由 | 灵活自由，行李方便 | 疲劳，停车难，费用高（油费+过路费+停车费） |

**大交通对规划的影响**：
- **第一天行程**：
  - 高铁/飞机：到达时间决定第一天行程开始时间，需要考虑从车站/机场到酒店的交通
  - 自驾：出发时间灵活，可以早上出发，中午到达，下午开始行程
- **最后一天行程**：
  - 高铁/飞机：返程时间决定最后一天行程结束时间，需要考虑从酒店到车站/机场的交通
  - 自驾：返程时间灵活，可以下午结束行程，晚上返程
- **住宿安排**：
  - 高铁/飞机：住宿安排在车站/机场附近或市中心
  - 自驾：住宿需要有停车场

---

#### 3.3.2 市内交通方式的影响

**市内交通方式分类**：

| 市内交通方式 | 适用场景 | 优点 | 缺点 |
|--------------|----------|------|------|
| **地铁** | 大城市，景点之间距离较远 | 快捷、准时、便宜 | 高峰期拥挤，需要换乘 |
| **公交** | 地铁不方便的地方 | 便宜、覆盖广 | 慢、不准时、需要换乘 |
| **打车** | 短途、携带行李、老人小孩 | 快捷、方便、门到门 | 费用高，高峰期难打车 |
| **共享单车** | 短途（1-3公里），天气好 | 灵活、便宜、锻炼身体 | 受天气影响，需要停车点 |
| **步行** | 超短途（<1公里），景点密集区 | 免费、自由、可以逛 | 慢、累、受天气影响 |
| **自驾** | 景点分散、公共交通不方便 | 灵活、自由、行李方便 | 停车难、费用高、疲劳 |

**市内交通对规划的影响**：
- **景点选择**：
  - 公共交通：优先选择公共交通便利的景点（地铁沿线、公交直达）
  - 自驾：可以选择公共交通不方便的景点（郊区、山区）
- **景点顺序**：
  - 公共交通：按地铁/公交线路排序，减少换乘
  - 自驾：按路线最优排序，考虑停车场位置
- **每天景点数量**：
  - 公共交通：景点之间交通时间长，每天景点数量适当减少
  - 自驾：景点之间交通时间短，每天景点数量可以适当增加
- **餐饮安排**：
  - 公共交通：午餐安排在景点附近，不需要专门开车去餐厅
  - 自驾：可以开车去更远的特色餐厅

**选择维度**：

| 维度 | 权重 | 说明 |
|------|------|------|
| **距离** | 40% | 距离是最主要的决定因素 |
| **时间** | 25% | 可用时间决定选择哪种交通方式 |
| **费用** | 15% | 预算档位影响交通方式选择 |
| **便利性** | 15% | 携带行李、老人小孩、天气等影响便利性 |
| **体验性** | 5% | 特色交通方式（如游船、缆车）可以增加体验 |

**按距离选择通行方式**：

| 景点间距离 | 推荐通行方式 | 备选通行方式 | 说明 |
|------------|--------------|--------------|------|

| **500米-2公里** | 共享单车 | 步行 | 短途，骑行快捷方便 |

| **5-15公里** | 地铁/打车 | 公交 | 中长途，地铁优先，打车备选 |

| **> 30公里** | 自驾/高铁 | 打车 | 超长途，自驾或高铁，打车费用高 |

**按人群选择通行方式**：

| 人群类型 | 优先通行方式 | 说明 |
|----------|--------------|------|
| **单人** | 公共交通（地铁/公交） | 灵活自由，费用低 |
| **情侣** | 地铁/打车/特色交通 | 可以尝试浪漫的特色交通（如游船） |
| **亲子** | 自驾/打车 | 减少换乘，避免长时间步行，携带儿童用品方便 |
| **家庭** | 自驾/打车 | 人多，公共交通不方便，自驾或打车更舒适 |
| **朋友** | 公共交通（地铁/公交） | 人多可以一起坐地铁，费用低，体验当地生活 |
| **老人** | 自驾/打车 | 减少步行和换乘，避免高峰期，舒适安全 |

**按预算选择通行方式**：

| 预算档位 | 优先通行方式 | 说明 |
|----------|--------------|------|
| **经济** | 公共交通（地铁/公交） | 费用最低 |
| **适中** | 地铁为主，打车为辅 | 综合考虑时间和费用 |
| **舒适** | 打车为主，地铁为辅 | 舒适快捷，费用适中 |
| **奢华** | 专车/包车 | 门到门服务，舒适奢华 |

**特殊场景的通行方式选择**：

| 特殊场景 | 推荐通行方式 | 说明 |
|----------|--------------|------|
| **携带行李** | 打车/自驾 | 避免搬运行李换乘 |
| **下雨天** | 打车/地铁 | 避免骑行和步行 |
| **高峰期** | 地铁 | 避免打车堵车 |
| **景点密集区** | 步行/共享单车 | 距离近，步行可以逛 |
| **郊区景点** | 自驾/打车 | 公共交通不方便 |
| **山区景点** | 自驾/景区大巴 | 公共交通不方便，需要爬山 |
| **夜间出行** | 打车 | 公共交通可能停运，安全考虑 |

#### 3.3.4 自驾的特殊规则

**目的地适配性判断**：

| 目的地类型 | 是否适合自驾 | 说明 |
|------------|--------------|------|
| **大城市中心** | 不太适合 | 停车难、堵车、限行、费用高 |
| **郊区/山区** | 适合 | 公共交通不方便，自驾灵活 |
| **多景点跨城** | 适合 | 灵活自由，行李方便 |
| **单城市深度游** | 不太适合 | 市内公共交通更方便，停车难 |
| **亲子/老人游** | 适合 | 减少换乘，舒适安全 |
| **朋友游** | 可以考虑 | 人多分摊费用，灵活自由 |

**自驾对规划的影响**：
- **景点选择**：
  - 可以选择公共交通不方便的景点（郊区、山区）
  - 优先选择有停车场的景点
- **景点顺序**：
  - 按路线最优排序，考虑停车场位置
  - 避免在城市中心频繁开车（堵车、停车难）
- **每天景点数量**：
  - 景点之间交通时间短，每天景点数量可以适当增加
  - 但需要考虑驾驶疲劳，不要安排过多
- **餐饮安排**：
  - 可以开车去更远的特色餐厅
  - 优先选择有停车场的餐厅
- **住宿安排**：
  - 必须选择有停车场的酒店
  - 可以选择市郊的酒店（价格便宜，停车方便）

**自驾的注意事项**：
- **驾驶时间**：每天驾驶时间不超过4小时，避免疲劳驾驶
- **停车费用**：大城市停车费用高，需要计入预算
- **限行政策**：大城市可能有限行政策，需要提前了解
- **景区交通管制**：部分景区可能有交通管制，需要停在景区外换乘
- **油费/过路费**：需要计入预算
- **租车/还车**：如果是租车，需要考虑租车/还车时间和地点

### 3.4 出行方式影响的灵活机制

#### 3.4.1 设计理念

出行方式对规划的影响不应该是硬性约束，而应该是**灵活的、可调节的**。在某些场景下，出行方式对规划的影响很大；在另一些场景下，出行方式对规划的影响很小，甚至可以忽略。

**核心原则**：
1. **影响强度分级**：出行方式对规划的影响分为强、中、弱三个等级
2. **场景驱动**：根据具体场景（人群、目的地、景点分布、预算）判断影响强度
3. **灵活应用**：根据影响强度决定是否应用出行方式的影响规则
4. **用户优先**：用户明确指定的出行方式优先，但影响强度仍需根据场景判断

---

#### 3.4.2 影响强度分级

| 影响强度 | 说明 | 应用规则 | 典型场景 |
|----------|------|----------|----------|
| **强影响** | 出行方式显著影响规划结果 | 完整应用出行方式的所有影响规则 | 亲子游、老人游、郊区景点、跨城游、自驾 |
| **中影响** | 出行方式部分影响规划结果 | 应用部分影响规则（如景点顺序、通行建议），但不影响景点选择 | 朋友游、家庭游、混合目的地、公共交通 |
| **弱影响** | 出行方式对规划结果影响很小 | 仅提供通行建议，不影响景点选择和行程安排 | 单人游、情侣游、市中心景点密集区、1天短途游 |

---

#### 3.4.3 影响强度判断规则

影响强度由以下5个维度综合判断，每个维度有不同的权重：

| 判断维度 | 权重 | 强影响条件 | 中影响条件 | 弱影响条件 |
|----------|------|------------|------------|------------|
| **人群类型** | 30% | 亲子、老人 | 家庭、朋友 | 单人、情侣 |
| **目的地类型** | 25% | 郊区/山区/跨城 | 混合（市中心+郊区） | 纯市中心 |
| **景点分布** | 20% | 景点分散（距离>5公里） | 景点中等分散（2-5公里） | 景点密集（<2公里） |
| **出行天数** | 15% | >5天 | 3-5天 | 1-2天 |
| **预算档位** | 10% | 舒适/奢华 | 适中 | 经济 |

**综合判断公式**：
```
影响强度得分 = 人群类型得分×30% + 目的地类型得分×25% + 景点分布得分×20% + 出行天数得分×15% + 预算档位得分×10%

强影响：得分 >= 70分
中影响：40分 <= 得分 < 70分
弱影响：得分 < 40分
```

**各维度得分**：
- 人群类型：亲子/老人=100分，家庭/朋友=60分，单人/情侣=20分
- 目的地类型：郊区/山区/跨城=100分，混合=60分，纯市中心=20分
- 景点分布：分散=100分，中等分散=60分，密集=20分
- 出行天数：>5天=100分，3-5天=60分，1-2天=20分
- 预算档位：舒适/奢华=100分，适中=60分，经济=20分

---

#### 3.4.4 不同影响强度下的应用规则

**强影响场景**：
- 景点选择：优先选择符合出行方式的景点（公共交通便利 or 有停车场）
- 景点顺序：按出行方式优化景点顺序（按交通线路 or 按路线最优）
- 每天景点数量：根据出行方式调整（公共交通时间长则减少，自驾时间短则增加）
- 餐饮安排：根据出行方式选择餐厅（公共交通选景点附近，自驾可选更远餐厅）
- 住宿安排：根据出行方式选择住宿（车站/机场附近 or 有停车场）
- 通行建议：提供详细的景点间通行方式建议

**中影响场景**：
- 景点选择：不影响核心景点选择，仅在辅助景点选择时考虑出行方式
- 景点顺序：按出行方式优化景点顺序
- 每天景点数量：不调整，按节奏配置
- 餐饮安排：不影响，按人群和预算选择
- 住宿安排：不影响，按人群和预算选择
- 通行建议：提供景点间通行方式建议

**弱影响场景**：
- 景点选择：完全不影响，按人群和风格选择
- 景点顺序：不影响，按地理距离和时间线排序
- 每天景点数量：不调整，按节奏配置
- 餐饮安排：不影响，按人群和预算选择
- 住宿安排：不影响，按人群和预算选择
- 通行建议：提供景点间通行方式建议（作为参考，用户可自行选择）

---

#### 3.4.5 用户指定出行方式的处理

- 用户明确指定且场景匹配：按用户指定的出行方式应用
- 用户明确指定但场景不匹配：按用户指定的出行方式应用，但在回复中提示可能的不便（如"市中心停车较难，建议公共交通"）
- 用户未指定：根据场景自动判断最优出行方式和影响强度

---

#### 3.4.6 影响强度的动态调整

- 用户反馈"景点太少" → 降低影响强度
- 用户反馈"交通不方便" → 提高影响强度
- 用户添加必去景点（交通不便） → 降低影响强度
- 目的地变更（从市中心改为郊区） → 提高影响强度

---

### 3.5 出行方式规划进行程的程度分级

#### 3.5.1 设计理念

出行方式要不要规划进行程、规划到什么程度，也是一个影响很大的点。在某些场景下，需要详细规划每个景点之间的具体交通方式、时间、费用；在另一些场景下，只需要提供大致建议即可，甚至完全不规划。

**核心原则**：
1. **规划程度分级**：出行方式规划进行程的程度分为详细规划、简要规划、不规划三个等级
2. **场景驱动**：根据具体场景（人群、目的地、出行方式、用户需求）判断规划程度
3. **与影响强度联动**：规划程度与影响强度（强/中/弱）相关但不完全等同
4. **用户优先**：用户明确要求详细规划时，按用户要求执行

---

#### 3.5.2 规划程度分级

| 规划程度 | 说明 | 行程中体现 | 典型场景 |
|----------|------|------------|----------|
| **详细规划** | 每个景点之间的交通方式、时间、费用都详细规划 | 行程中明确标注"地铁2号线，约20分钟，4元" | 亲子游、老人游、首次到访、公共交通、跨城游 |
| **简要规划** | 仅提供大致的交通方式建议，不详细到时间和费用 | 行程中标注"建议地铁/打车"，不标注具体时间和费用 | 朋友游、家庭游、混合出行方式、重复到访 |
| **不规划** | 完全不规划交通方式，仅提供景点和时间安排 | 行程中不体现交通方式，用户自行安排 | 单人游、情侣游、市中心景点密集区、自驾、1天短途游 |

---

#### 3.5.3 规划程度判断规则

规划程度由以下4个维度综合判断，每个维度有不同的权重：

| 判断维度 | 权重 | 详细规划条件 | 简要规划条件 | 不规划条件 |
|----------|------|--------------|--------------|------------|
| **人群类型** | 30% | 亲子、老人 | 家庭、朋友 | 单人、情侣 |
| **出行方式** | 30% | 公共交通 | 混合 | 自驾 |
| **目的地类型** | 25% | 郊区/山区/跨城 | 混合 | 纯市中心 |
| **出行天数** | 15% | >5天 | 3-5天 | 1-2天 |

**综合判断公式**：
```
规划程度得分 = 人群类型得分×30% + 出行方式得分×30% + 目的地类型得分×25% + 出行天数得分×15%

详细规划：得分 >= 70分
简要规划：40分 <= 得分 < 70分
不规划：得分 < 40分
```

**各维度得分**：
- 人群类型：亲子/老人=100分，家庭/朋友=60分，单人/情侣=20分
- 出行方式：公共交通=100分，混合=60分，自驾=20分
- 目的地类型：郊区/山区/跨城=100分，混合=60分，纯市中心=20分
- 出行天数：>5天=100分，3-5天=60分，1-2天=20分

---

#### 3.5.4 不同规划程度下的行程体现

**详细规划**：
- 每个景点之间明确标注交通方式、时间、费用
- 示例："故宫 → 景山公园：步行，约10分钟，免费"
- 示例："颐和园 → 圆明园：地铁4号线，约15分钟，3元"
- 包含换乘提示、注意事项

**简要规划**：
- 仅提供交通方式建议，不标注时间和费用
- 示例："故宫 → 景山公园：建议步行"
- 示例："颐和园 → 圆明园：建议地铁或打车"

**不规划**：
- 完全不体现交通方式
- 行程中只有景点名称、时间安排、介绍

---

#### 3.5.5 规划程度与影响强度的联动

| 影响强度 | 规划程度 | 说明 |
|----------|----------|------|
| **强影响** | 通常详细规划 | 强影响场景下，出行方式显著影响规划，通常需要详细规划交通 |
| **中影响** | 通常简要规划 | 中影响场景下，出行方式部分影响规划，通常简要规划交通即可 |
| **弱影响** | 通常不规划 | 弱影响场景下，出行方式对规划影响很小，通常不需要规划交通 |

**但也有例外**：
- 强影响但自驾：影响强度强（如亲子游郊区），但规划程度可能是不规划（因为自驾用户自行安排）
- 弱影响但公共交通：影响强度弱（如单人游市中心），但用户可能要求详细规划（首次到访）

---

#### 3.5.6 用户需求的特殊处理

- 用户明确要求"详细规划交通" → 按详细规划执行
- 用户明确要求"不要规划交通" → 按不规划执行
- 用户反馈"交通信息太详细" → 降低规划程度
- 用户反馈"交通信息不够" → 提高规划程度

## 4. 各阶段详细规则

### 4.1 阶段1：参数识别

**核心职责**：使用LLM解析用户输入，提取规划所需的各项参数。

**输入**：用户对话（可能包含多轮对话历史）

**输出**：规划参数对象（PlanRequest）

**识别参数清单**：

| 参数名 | 含义 | 是否必须 | 默认值 | 取值范围 |
|--------|------|----------|--------|----------|
| destination | 目的地 | 是 | 无 | 全国/省/市/区县/具体地点 |
| days | 出行天数 | 否 | 3 | 1-15天 |
| origin | 出发点 | 否 | 空 | 具体地点 |
| travelers | 出行人数 | 否 | 1 | 1-99人 |
| return_point | 返回点 | 否 | 空 | 具体地点 |
| group_type | 人群类型 | 否 | 单人 | 单人/情侣/亲子/家庭/朋友/老人 |
| budget_level | 预算档位 | 否 | 适中 | 经济/适中/舒适/奢华 |
| style | 旅行风格 | 否 | 美食+人文 | 美食/人文/网红/小众/亲子/自然 |
| pace | 节奏 | 否 | 适中 | 轻松/适中/暴走 |
| traffic_mode | 出行方式 | 否 | 公共交通 | 自驾/公共交通/骑行/步行/混合 |
| must_include_poi | 必去景点 | 否 | 空 | 景点名称数组 |
| exclude_poi | 排除景点 | 否 | 空 | 景点名称数组 |
| interests | 兴趣标签 | 否 | 空 | 兴趣标签数组 |

**核心规则**：
1. **目的地必须识别**：如果无法识别目的地，回复用户询问目的地
2. **参数兜底**：未识别的参数使用默认值
3. **参数收束**：超过范围的参数收束到合理范围（详见3.1节）
4. **上下文继承**：多轮对话中，后续对话继承已识别的参数
5. **参数更新**：用户明确修改的参数更新，其他参数保持不变

---

### 4.2 阶段2：景点检索与筛选

**核心职责**：对目的地做同名处理，然后行政分级枚举，POI检索，最后按照人群筛选景点。

**输入**：规划参数对象（PlanRequest）

**输出**：候选景点池（筛选后的景点列表）

**规则执行顺序**：
1. 目的地同名地点处理
2. 行政分级枚举
3. POI检索
4. 按照人群筛选

> **注意**：主/子POI识别移到阶段3（景点聚类与分组）进行。

#### 4.2.1 目的地同名地点处理（第一步）

**地名重复处理**：
1. 优先以目的地的地点为先
2. 如果无法确定，通过用户对话确认
3. 避免地点飘逸

**景点名重复处理**：
1. 优先以目的地所在行政区域的景点为先
2. 如果无法确定，通过用户对话确认
3. 避免景点飘逸

#### 4.2.2 行政分级枚举（第二步）

根据目的地的行政等级，分级枚举景点：

| 目的地等级 | 检索范围 | 优先级 |
|------------|----------|--------|
| **省级** | 枚举省内各市的景点 | 按市分隔，每个市的景点作为一组 |
| **市级/区级/地点级** | 先把当前市级/区级/地点作为1级推荐，再往上枚举至省下的地点作为补充 | 1级推荐优先，补充景点次之 |

#### 4.2.3 POI检索（第三步）

**检索来源**：
1. 本地行政区域数据：优先从本地行政区域数据中检索
2. 高德/腾讯POI搜索：本地数据不足时，调用第三方API检索
3. 必打卡地标库：从数据库中读取必去地标，强制注入

**检索类别**：

| 类别 | 说明 | 是否主规划 |
|------|------|------------|
| **景点** | 风景名胜、历史古迹、公园、博物馆等 | 是（主规划） |
| **美食** | 餐厅、小吃、美食街等 | 否（辅助） |
| **购物** | 商场、商业街、市场等 | 否（辅助） |
| **夜生活** | 酒吧、夜市、夜景等 | 否（辅助） |

**核心规则**：景点作为主规划路径，美食、购物、夜生活只做辅助，不参与主规划路径。

#### 4.2.4 按照人群筛选（第四步）

详见3.2节（人群参数对出行规划的影响点）。

**硬性约束筛选**：
1. 必去景点：must_include_poi中的景点必须保留
2. 排除景点：exclude_poi中的景点必须过滤
3. 中国区域校验：仅保留中国境内的景点
4. 开放状态校验：过滤已关闭、停业、拆迁的景点

**本阶段输出**：
候选景点池，包含以下信息：
- 景点名称、类型、经纬度、行政区域
- 评分、权重
- 建议游玩时长、开放时间
- 门票价格
- 人群标签、风格标签
- 景点强度（高强度/中强度/低强度）

---

### 4.3 阶段3：景点聚类与分组

**核心职责**：首先做主/子POI的识别规划，然后将候选景点池中的景点，按地理距离、行政区域、景点类型进行聚类和分组。

**输入**：候选景点池

**输出**：景点聚类（多个景点组，每组包含地理位置相近的景点）

**规则执行顺序**：
1. 主/子POI的识别规划
2. 景点的分组
3. 按照地理距离的规划

#### 4.3.1 主/子POI识别规划（第一步）

**大型景区识别**：从大型景区库中识别大型景区（如故宫、西湖、大明湖），大型景区作为主POI。

**子POI标记**：大型景区内的小景点作为子POI（如故宫内的太和殿、乾清宫）。

**权重调整**：
- 主POI：权重高，优先规划
- 子POI：权重降低，作为主POI的补充，不单独作为规划点位

**去重逻辑**：
- 如果主POI已经在行程中，子POI只作为点位介绍，不单独规划
- 如果主POI不在行程中，子POI可以单独规划，但优先级降低

**聚类中的主/子POI处理**：
- 主POI作为聚类的核心，子POI依附于主POI所在的聚类
- 子POI不单独成组，而是作为主POI的内部点位
- 聚类时只考虑主POI和独立景点的地理距离，子POI不参与聚类

#### 4.3.2 景点的分组（第二步）

**聚类目标**：
1. 地理就近：地理位置相近的景点聚为一组
2. 行政区域一致：同一行政区域的景点优先聚为一组
3. 景点类型协调：同一组内景点类型协调（避免全是博物馆或全是公园）
4. 组数合理：聚类数量与出行天数匹配（通常组数 = 天数或略多于天数）

**基于行政区域的聚类**：
1. 按区县分组：同一区县的景点优先聚为一组
2. 按市分组：跨市行程中，同一市的景点聚为一组
3. 跨城污染过滤：避免同一组内包含不同城市的景点（除非是跨城日）

**基于景点类型的聚类**：
1. 类型协调：同一组内景点类型多样化（人文+自然+美食）
2. 顶级地标分组：顶级地标（如故宫、长城）单独成组或作为组的核心
3. 同地标词去重：同一地标词的景点（如"天安门广场"和"天安门城楼"）优先聚为一组

#### 4.3.3 按照地理距离的规划（第三步）

**基于地理距离的聚类**：
1. 计算距离矩阵：计算所有景点之间的地理距离
2. 贪心聚类：
   - 从评分最高的景点开始
   - 将距离最近的景点加入同一组
   - 直到组内景点数量达到上限（通常每天3-5个）
   - 然后开始下一组
3. 圈层分配：
   - 以目的地中心为圆心
   - 按距离划分为多个圈层（如0-3公里、3-10公里、10公里以上）
   - 每个圈层的景点聚为一组或多组

**聚类数量控制**：

| 出行天数 | 聚类数量 | 说明 |
|----------|----------|------|
| 1天 | 1组 | 单日行程 |
| 2-3天 | 2-3组 | 每组对应1天 |
| 4-7天 | 4-7组 | 每组对应1天，可能有跨城组 |
| 8-15天 | 8-15组 | 每组对应1天，跨城/跨省组 |

**本阶段输出**：
景点聚类，包含以下信息：
- 聚类ID、聚类名称（如"市中心经典组"、"郊区自然风光组"）
- 组内景点列表
- 聚类中心经纬度
- 聚类覆盖的行政区域
- 聚类评分（组内景点平均评分）

---

### 4.4 阶段4：按天分配与切分

**核心职责**：将景点聚类分配到每天，考虑跨天区域去重、时间跨度收束、住宿点等因素。

**输入**：景点聚类

**输出**：每日景点（每天分配的景点列表）

#### 4.4.1 基于旅行体验曲线的分配（核心策略）

**人的旅行体验曲线**：
```
第1天：兴奋但疲劳（长途旅行后）→ 轻松入门
第2-3天：体力充沛、兴趣最高 → 核心景点
第4-5天：体力开始下降 → 中等强度
第6天+：疲劳累积 → 轻松收尾
```

**分配规则**：

| 天数 | 体验状态 | 分配策略 | 景点类型 |
|------|----------|----------|----------|
| **第1天** | 兴奋但疲劳 | 轻松入门，安排市中心/交通便利的景点 | 低强度：博物馆、公园、街区 |
| **第2-3天** | 体力充沛 | 核心景点，安排最重要、最耗体力的景点 | 高强度：长城、爬山、大型景区 |
| **第4-5天** | 体力下降 | 中等强度，安排次重要景点 | 中强度：历史古迹、文化景点 |
| **第6天+** | 疲劳累积 | 轻松收尾，安排返程车站附近景点 | 低强度：购物、休闲、美食 |

#### 4.4.2 基于体力曲线的分配

**体力交替原则**：避免连续安排高强度景点，高强度和低强度交替。

| 景点强度 | 说明 | 示例 |
|----------|------|------|
| **高强度** | 需要大量步行、爬山、耗时久 | 长城、泰山、黄山、大型景区 |
| **中强度** | 中等步行、耗时中等 | 故宫、颐和园、兵马俑 |
| **低强度** | 少量步行、耗时短、可休息 | 博物馆、公园、街区、购物 |

**分配规则**：
- 高强度景点后必须安排低强度景点（休息恢复）
- 最多连续2天中等强度
- 每周最多1-2个高强度景点

#### 4.4.3 基于景点热度的分配

- 热门景点安排在工作日（避免周末人流高峰）
- 室外景点安排在天气好的日子
- 室内景点可以安排在天气不好的日子（如下雨）
- 早开景点（如故宫8:30开门）安排在上午
- 晚开景点（如商场10:00开门）安排在下午

#### 4.4.4 基于住宿区域的分配

- 同一住宿区域的景点安排在连续的几天
- 避免频繁更换住宿区域（每2-3天换一次住宿比较合理）

#### 4.4.5 跨天区域去重规则

1. 按区县去重：同一区县的景点尽量安排在同一天
2. 按市去重：跨市行程中，同一市的景点尽量安排在连续的几天
3. 避免区域重复：如第1天在杭州，第2天在绍兴，第2天的行程不应包含杭州的地点

#### 4.4.6 时间跨度收束规则

1. 按可支撑区域数收束：如果目的地可支撑的区域数 < 天数，收束天数
2. 大时间跨度处理（详见3.1.2节）

#### 4.4.7 住宿点考虑规则

1. 住宿点作为第二天起点：如果规划了住宿，住宿点作为第二天的起点
2. 住宿区域推荐：只推荐大致区域，不推荐具体酒店（可配置）
3. 最后一天住宿：最后一天住宿考虑返程车站附近

#### 4.4.8 返程车站考虑规则

如果用户提供了返程车站信息：
1. 最后一天景点安排在返程车站附近
2. 时间倒推：根据返程出发时间，倒推最后一天的行程安排
3. 交通时间预留：预留从最后一个景点到车站的交通时间

**本阶段输出**：
每日景点，包含以下信息：
- 第几天、日期
- 当天景点列表（按顺序）
- 当天主题（如"中轴线经典"、"皇家园林"）
- 住宿推荐区域
- 当天总游玩时长预估

### 4.5 阶段5：每日排序与时间线

**核心职责**：对每天内的景点进行排序，然后应用时间线（上午/中午/下午/晚上），考虑开放时间、建议游玩时长等因素。

**输入**：每日景点

**输出**：时间线行程（每天内景点顺序+时间段）

#### 4.5.1 基于人流高峰的排序（核心策略）

| 景点类型 | 人流高峰 | 最佳游览时间 |
|----------|----------|--------------|
| **热门景点**（故宫、长城） | 10:00-15:00 | 开门时（8:30-10:00）或闭馆前（15:00-17:00） |
| **室外景点** | 12:00-14:00（高温） | 上午（09:00-12:00）或傍晚（16:00-18:00） |
| **室内景点**（博物馆） | 14:00-16:00 | 上午（09:00-12:00）或闭馆前 |
| **购物/商场** | 14:00-18:00 | 晚上（18:00-21:00） |
| **夜景** | 19:00-21:00 | 日落后（19:00-21:00） |

#### 4.5.2 基于光照和拍照的排序

| 景点朝向 | 最佳拍照时间 |
|----------|--------------|
| **朝东** | 上午（09:00-11:00） |
| **朝南** | 上午或下午 |
| **朝西** | 下午（15:00-17:00） |
| **朝北** | 中午（11:00-13:00） |
| **全景/俯瞰** | 傍晚（17:00-19:00） |

#### 4.5.3 基于用餐的排序

- 上午景点结束在美食街附近（方便午餐）
- 下午景点结束在晚餐区域附近
- 避免景点和餐厅距离过远（步行不超过10分钟）

#### 4.5.4 基于地理距离的排序

1. 贪心最近邻：从第一个景点开始，每次选择距离最近的下一个景点
2. 路线优化：避免来回折返，尽量形成环形或单向路线
3. 起点和终点：第1天起点考虑出发点/住宿点，最后一天终点考虑返回点/返程车站

#### 4.5.5 基于开放时间的精确排序

- 精确计算开门时间、最后入场时间、闭馆时间、每周闭馆日
- 只在开放时间内安排景点
- 考虑最后入场时间（如故宫16:00停止入场，17:00闭馆）
- 每周闭馆日不安排该景点

#### 4.5.6 基于交通时间的精确排序

- 精确计算景点之间的交通时间
- 考虑交通高峰时段（高峰时段交通时间增加50%）
- 每个景点之间预留15-30分钟缓冲时间
- 避免在交通高峰时段安排长距离移动

#### 4.5.7 基于主/子POI的排序

- 主POI（大型景区）作为一个整体安排在时间段内
- 子POI（景区内小景点）只作为点位介绍，不单独占用时间段
- 规划景区内部的游览路线（入口出口、内部景点顺序、代步工具、最佳拍照点、休息点）

#### 4.5.8 时间线应用规则

| 时段 | 时间范围 | 安排内容 |
|------|----------|----------|
| **上午** | 09:00-12:00 | 主要景点（人文/历史/大景点） |
| **中午** | 12:00-14:00 | 午餐 + 休息 |
| **下午** | 14:00-18:00 | 次要景点（自然/公园/购物） |
| **晚上** | 18:00-21:00 | 晚餐 + 夜景/夜生活 |

**节奏与景点数量**：

| 节奏 | 每天景点数量 | 时间安排特点 |
|------|--------------|--------------|
| **轻松** | 3个 | 每个景点游玩时间长，中间休息时间多 |
| **适中** | 4个 | 平衡游玩和休息 |
| **暴走** | 5个 | 每个景点游玩时间短，尽量多游览 |

**本阶段输出**：
时间线行程，包含以下信息：
- 第几天、日期
- 时间段（上午/中午/下午/晚上）
- 每个时间段的景点/活动
- 每个景点的建议游玩时长
- 每个景点的开放时间
- 用餐时间和推荐餐厅类型

### 4.6 阶段6：辅助点位与通行建议（含检视与补充）

**核心职责**：在主行程基础上，添加美食、购物、夜生活等辅助点位，并提供景点间通行方式建议。**规划完成后检视整体行程是否符合要求，不符合要求从候选景点池没入选和辅助点位中挑选穿插进去，后续暂不更改。**

**输入**：时间线行程

**输出**：完整行程（景点+美食+购物+夜生活+通行建议）

**规则执行顺序**：
1. 辅助点位推荐（美食、购物、夜生活）
2. 通行建议
3. 规划完成后检视整体行程
4. 不符合要求从候选景点池没入选和辅助点位中挑选穿插进去
5. 后续暂不更改（阶段7、8、9不更改景点安排）

#### 4.6.1 辅助点位推荐规则

**美食推荐**：
- 用餐时间：午餐（12:00-13:30）和晚餐（18:00-19:30）
- 推荐位置：景点附近，步行可达
- 按人群推荐（详见3.2节）
- 按预算推荐（详见3.1.4节）

**购物推荐**：
- 推荐时间：下午或晚上
- 推荐位置：景点附近或行程终点
- 按人群和风格推荐

**夜生活推荐**：
- 推荐时间：晚上（19:00以后）
- 推荐位置：住宿附近或行程终点
- 按人群和风格推荐

**辅助点位不参与跨天去重**：美食、购物、夜生活只做辅助，不参与主规划路径的跨天去重，可以重复出现。

#### 4.6.2 通行建议规则

详见3.3节（出行方式的影响规则）、3.4节（出行方式影响的灵活机制）、3.5节（出行方式规划进行程的程度分级）。

#### 4.6.3 规划完成后的检视与补充规则

**检视维度**（8个维度）：

| 检视维度 | 检视内容 | 合格标准 |
|----------|----------|----------|
| **景点数量** | 每天景点数量是否符合节奏配置 | 轻松3个/适中4个/暴走5个 |
| **景点质量** | 是否包含必去景点、顶级地标 | 必去景点全部包含 |
| **人群匹配** | 景点是否符合人群类型 | 亲子/老人景点占比符合要求 |
| **时间合理** | 每天时间安排是否合理 | 不超时、不冲突、有休息 |
| **交通合理** | 景点间交通时间是否合理 | 不超过2小时/次 |
| **预算合理** | 总预算是否在预算档位范围内 | 上下浮动不超过20% |
| **跨天去重** | 不同天景点是否跨区域重复 | 同一区县不跨天重复 |
| **强度合理** | 高强度景点是否连续安排 | 高强度后有低强度休息 |

**不符合要求的补充规则**：

**补充来源**：
1. 候选景点池没入选的景点：从阶段2筛选后但没入选的景点中挑选
2. 辅助点位：从美食、购物、夜生活等辅助点位中挑选

**补充场景**：

| 不符合场景 | 补充策略 | 补充来源 |
|------------|----------|----------|
| **景点数量不足** | 增加景点 | 候选景点池没入选的景点 |
| **缺少必去景点** | 插入必去景点 | 候选景点池没入选的景点 |
| **人群匹配不足** | 增加人群相关景点 | 候选景点池没入选的景点 |
| **时间有空隙** | 插入辅助点位 | 美食、购物、夜生活 |
| **强度过高** | 替换为低强度景点 | 候选景点池没入选的低强度景点 |
| **跨天重复** | 替换为其他区域景点 | 候选景点池没入选的其他区域景点 |

**补充规则**：
- 优先从候选景点池没入选的景点中挑选（保证景点质量）
- 辅助点位（美食、购物、夜生活）只作为时间空隙的补充
- 补充后重新检视，直到符合要求
- **后续暂不更改**（阶段7、8、9不更改景点安排）

**本阶段输出**：
完整行程，包含以下信息：
- 主行程（景点+时间线）
- 辅助点位（美食+购物+夜生活）
- 通行建议（景点间交通方式）
- 住宿推荐区域

### 4.7 阶段7：预算计算与优化

**核心职责**：计算行程的各项预算（餐饮、住宿、交通、门票），并根据预算档位进行优化调整。

**输入**：完整行程

**输出**：带预算行程（餐饮+住宿+交通+门票+总预算）

**预算计算规则**（详见3.1.4节）：
- 餐饮预算：每顿预算 × 2顿 × 天数 × 人数
- 住宿预算：每间预算 × 房间数 × 晚数
- 交通预算：每天交通预算 × 天数 × 人数 + 大交通费用
- 门票预算：收费景点门票价格累加
- 总预算：餐饮 + 住宿 + 交通 + 门票

**预算优化规则**：
- 预算超支：降低住宿档位、减少收费景点、调整餐饮推荐、优化交通方式
- 预算不足：提升住宿档位、增加收费景点、调整餐饮推荐、优化交通方式

**本阶段输出**：
带预算行程，包含以下信息：
- 餐饮预算（明细+总计）
- 住宿预算（明细+总计）
- 交通预算（明细+总计）
- 门票预算（明细+总计）
- 总预算
- 人均预算

### 4.8 阶段8：LLM优化与文案生成

**核心职责**：使用LLM对行程进行智能优化，并生成出发语、每日灵感、回复文案、人文介绍等内容。

**输入**：带预算行程

**输出**：优化后行程（智能优化+人文介绍+出发语+每日灵感+回复文案）

**LLM智能优化规则**：
- 景点优化：补充遗漏的重要景点、替换评分低的景点、优化景点排序
- 行程优化：优化时间安排、用餐推荐、住宿推荐
- 人文介绍生成：为每个景点生成历史背景、文化价值、名人轶事、游览建议、语音介绍

**文案生成规则**：
- 出发语：富有感染力，激发行走天下的勇气
- 每日灵感：每天一句旅行灵感
- 回复文案：行程概述、必去景点、行程亮点、预算概览、行动号召、调整提示
- 品牌气质：鼓励用户走出去，去旅行，去探索，激发行走天下的勇气

**RAG知识检索规则**（如果启用）：
- 检索时机：用户询问景点人文介绍时、用户询问历史名人相关信息时、生成景点人文介绍时
- 检索内容：景点历史背景、名人轶事、文化价值、游览建议
- 知识干预：后台可配置知识库内容，人为干预检索结果

**本阶段输出**：
优化后行程，包含以下信息：
- LLM优化后的行程
- 每个景点的人文介绍
- 出发语
- 每日灵感
- 回复文案
- 语音介绍内容

### 4.9 阶段9：验证与输出

**核心职责**：验证行程的合理性，然后格式化输出，存储到数据库，返回给前端。

**输入**：优化后行程

**输出**：最终行程（格式化、验证通过、已存储）

**行程验证规则**：
- 景点验证：不重复、开放、在中国、必去包含、排除不包含
- 时间验证：不冲突、游玩时长合理、交通时间合理、用餐休息预留
- 预算验证：总预算合理、各项预算合理、人均预算合理
- 跨天验证：区域不重复、每天数量合理、住宿连续

**验证失败处理**：
- 自动修复：对于可以自动修复的问题，自动修复
- 降级处理：对于无法自动修复的问题，降级处理
- 记录日志：记录验证失败的原因和处理方式
- 返回警告：在返回结果中包含警告信息

**格式化输出规则**：
- 数据结构：标准化的行程数据结构
- 地图数据：景点经纬度、路线坐标、标记点信息、路线颜色

**存储规则**：
- 用户关联：如果用户已登录，将行程与用户关联
- 会话关联：将行程与会话关联
- 唯一ID：生成唯一的行程ID
- 创建/更新时间：记录创建和更新时间

**本阶段输出**：
最终行程，包含以下信息：
- 行程ID
- 完整的行程数据（已验证、已格式化）
- 地图渲染数据
- 存储状态

## 5. 阶段间衔接关系

### 5.1 数据流

每个阶段的输出作为下一个阶段的输入，形成完整的数据流：
```
阶段1输出 → 阶段2输入 → 阶段2输出 → 阶段3输入 → ... → 阶段9输出
```

### 5.2 反馈循环

某些阶段之间存在反馈循环：
- 阶段2 → 阶段3：如果聚类效果不好，返回阶段2重新筛选景点
- 阶段4 → 阶段3：如果按天分配后发现聚类不合理，返回阶段3重新聚类
- 阶段5 → 阶段4：如果排序后发现时间冲突，返回阶段4重新分配
- 阶段7 → 阶段2：如果预算超支，返回阶段2重新筛选景点（增加免费景点）
- 阶段8 → 阶段5：LLM优化后可能调整景点排序，返回阶段5重新排序
- 阶段6内部：检视不符合要求，从候选景点池补充，重新检视

### 5.3 阶段优先级

当多个阶段的规则冲突时，按以下优先级处理：
1. **硬性约束**（最高优先级）：必去景点、排除景点、中国区域校验、开放时间
2. **用户明确指定**：用户明确指定的参数和要求
3. **阶段9验证规则**：行程验证规则
4. **阶段4分配规则**：按天分配和跨天去重规则
5. **阶段5排序规则**：每日排序和时间线规则
6. **阶段2筛选规则**：景点筛选规则
7. **阶段3聚类规则**：景点聚类规则
8. **其他规则**（最低优先级）：辅助点位、通行建议、预算优化

## 7. 总结

### 7.1 完整规则体系的价值

1. **规则完整性**：每个阶段都有明确的规则，不遗漏关键环节
