# 规划参数影响分析文档

> 文档版本：v1.0  
> 更新时间：2026-08-29  
> 适用范围：LLM识别出的规划参数对行程规划结果的影响分析

---

## 1. 文档概述

本文档详细分析LLM（大语言模型）从用户对话中识别出的各个规划参数，以及这些参数的不同取值对行程规划结果的具体影响。

**核心观点**：决定规划结果的首先是LLM识别出来的参数，参数值的不同会直接影响规划的景点选择、行程安排、预算计算、节奏控制等各个方面。

---

## 2. 参数总览

LLM识别出的规划参数共17个，按影响维度可分为以下几类：

| 分类 | 参数 | 取值范围 | 默认值 |
|------|------|----------|--------|
| **目的地相关** | `destination` | 全国/省/市/区县/具体地点 | 无（必须） |
| | `origin` | 具体地点 | 空 |
| | `return_point` | 具体地点 | 空 |
| | `return_station` | 车站名称 | 空 |
| | `return_station_type` | train/airport/bus | 空 |
| | `return_departure_time` | HH:MM | 空 |
| **时间相关** | `days` | 1-15天 | 3天 |
| | `span_unit` | day/week/month/year | day |
| | `span_value` | 数量 | 3 |
| | `daily_start_time` | HH:MM | 09:00 |
| | `daily_end_time` | HH:MM | 21:00 |
| **人群相关** | `travelers` | 1-99人 | 1人 |
| | `group_type` | 单人/情侣/亲子/家庭/朋友/老人 | 单人 |
| **偏好相关** | `budget_level` | 经济/适中/舒适/奢华 | 适中 |
| | `style` | 美食/人文/网红/小众/亲子/自然 | 美食+人文 |
| | `pace` | 轻松/适中/暴走 | 适中 |
| | `traffic_mode` | 自驾/公共交通/骑行/步行/混合 | 公共交通 |
| | `interests` | 兴趣标签数组 | 空 |
| **约束相关** | `must_include_poi` | 必去景点数组 | 空 |
| | `exclude_poi` | 排除景点数组 | 空 |
| **策略相关** | `plan_strategy` | traditional/spatial_temporal | traditional |

## 3. 各参数详细影响分析

### 3.1 destination（目的地）

**参数说明**：用户想去的旅行目的地，可以是全国、省、市、区县、具体地点等不同行政等级。

**取值范围**：
- 全国级：如"全国"
- 省级：如"山东省"、"浙江省"
- 市级：如"北京市"、"杭州市"
- 区县级：如"西湖区"、"朝阳区"
- 地点级：如"大明湖"、"故宫"

**对规划的影响**：

| 取值类型 | 影响维度 | 具体影响 |
|----------|----------|----------|
| **省级** | 景点枚举范围 | 枚举省内各市的景点，按市分隔做路径规划 |
| | 时间跨度收束 | 按省内可支撑的城市数收束天数 |
| | 聚类方式 | 按城市聚类，每个城市可能占1-2天 |
| **市级/区级/地点级** | 景点枚举范围 | 先把当前市级/区级/地点作为1级推荐，再往上枚举至省下的地点作为补充 |
| | 聚类方式 | 按地理距离聚类，每个聚类占1天 |
| | 跨天去重 | 按区县去重，避免同一区县景点跨天重复 |
| **所有类型** | 目的地定位 | 调用地理编码API定位目的地经纬度 |
| | 中国区域校验 | 仅规划中国境内目的地，境外返回拒绝 |
| | 天气查询 | 查询目的地天气 |
| | POI检索 | 以目的地为中心检索周边POI |

**影响权重**：⭐⭐⭐⭐⭐（最高，决定规划的基础范围）

---

### 3.2 days（天数）

**参数说明**：出行时间跨度，以天为单位。

**取值范围**：1-15天（超过15天会被收束）

**对规划的影响**：

| 取值范围 | 影响维度 | 具体影响 |
|----------|----------|----------|
| **1天** | 景点数量 | 每天2-5个景点（根据节奏） |
| | 行程安排 | 单日行程，不需要考虑住宿和跨天交通 |
| | 聚类数量 | 1个聚类 |
| **2-5天** | 景点数量 | 每天2-5个景点，总计4-25个景点 |
| | 行程安排 | 需要考虑住宿和跨天交通 |
| | 聚类数量 | 2-5个聚类，每个聚类占1天 |
| | 时间跨度收束 | 按可支撑的区域数收束天数 |
| **6-15天** | 景点数量 | 每天2-5个景点，总计12-75个景点 |
| | 行程安排 | 需要详细考虑住宿和跨天交通 |
| | 聚类数量 | 6-15个聚类，可能跨城市/跨省 |
| | 时间跨度收束 | 严格按可支撑的区域数收束天数 |

**与其他参数的联动**：
- `pace`（节奏）：每天景点数量 = pace对应的点位数量
- `group_type`（人群）：亲子/老人默认轻松节奏，每天景点少
- `destination`（目的地）：如果可支撑的区域数 < days，会收束days

**影响权重**：⭐⭐⭐⭐⭐（最高，决定规划的时间框架）

---

### 3.3 travelers（出行人数）

**参数说明**：出行的人数。

**取值范围**：1-99人

**对规划的影响**：

| 取值范围 | 影响维度 | 具体影响 |
|----------|----------|----------|
| **1人** | 预算计算 | 单人预算，住宿按1间房计算 |
| | 人群类型 | 默认group_type为"单人" |
| | 行程安排 | 可以更灵活，不需要考虑多人协调 |
| **2人** | 预算计算 | 双人预算，住宿按1间房计算（2人同住） |
| | 人群类型 | 默认group_type为"朋友"（中性默认值） |
| | 行程安排 | 需要考虑2人协调 |
| **3-4人** | 预算计算 | 多人预算，住宿按2间房计算 |
| | 人群类型 | 默认group_type为"朋友" |
| | 行程安排 | 需要考虑多人协调，可能需要更大的餐桌/房间 |
| **5人以上** | 预算计算 | 团体预算，住宿按多间房计算 |
| | 人群类型 | 默认group_type为"朋友" |
| | 行程安排 | 需要考虑团体协调，可能需要预约团体票 |

**与其他参数的联动**：
- `group_type`（人群类型）：如果用户明确指定了group_type，则根据group_type推断默认人数（情侣→2人，亲子→3人，家庭→4人）
- `budget_level`（预算）：总预算 = 人均预算 × 人数

**当前逻辑**：
- 如果用户明确指定了人数，使用用户指定的人数
- 如果用户没有指定人数，但指定了group_type，根据group_type推断默认人数
- 如果用户既没有指定人数，也没有指定group_type，默认1人

**影响权重**：⭐⭐⭐⭐（高，主要影响预算计算）

---

### 3.4 group_type（出行人群类型）

**参数说明**：出行的人群类型，影响节奏、景点选择、预算等。

**取值范围**：单人/情侣/亲子/家庭/朋友/老人

**对规划的影响**：

| 取值 | 影响维度 | 具体影响 |
|------|----------|----------|
| **单人** | 默认节奏 | 适中节奏，每天4个点位 |
| | 景点选择 | 可以选择更小众、更个性化的景点 |
| | 预算计算 | 单人预算 |
| | 住宿推荐 | 单人间/青旅 |
| **情侣** | 默认节奏 | 适中节奏，每天4个点位 |
| | 景点选择 | 倾向浪漫、网红打卡、夜景、私密餐厅 |
| | 预算计算 | 双人预算，住宿1间房 |
| | 住宿推荐 | 情侣酒店/精品酒店 |
| **亲子** | 默认节奏 | 轻松节奏，每天3个点位（自动调整） |
| | 景点选择 | 倾向亲子友好、游乐园、动物园、博物馆、科普类景点 |
| | 预算计算 | 3人预算（2大1小），住宿1间家庭房 |
| | 住宿推荐 | 亲子酒店/家庭房 |
| | 行程安排 | 中午需要午休，景点之间需要更多休息时间 |
| **家庭** | 默认节奏 | 适中节奏，每天4个点位 |
| | 景点选择 | 倾向全家友好、经典景点、文化景点 |
| | 预算计算 | 4人预算（2大2小），住宿2间房 |
| | 住宿推荐 | 家庭房/套房 |
| **朋友** | 默认节奏 | 暴走节奏，每天5个点位（自动调整） |
| | 景点选择 | 倾向网红打卡、夜生活、美食、购物 |
| | 预算计算 | 多人预算，住宿多间房 |
| | 住宿推荐 | 青旅/经济型酒店/民宿 |
| **老人** | 默认节奏 | 轻松节奏，每天3个点位（自动调整） |
| | 景点选择 | 倾向文化景点、公园、平缓景点，避免爬山/剧烈运动 |
| | 预算计算 | 2人预算，住宿1间房 |
| | 住宿推荐 | 舒适型酒店/低楼层房间 |
| | 行程安排 | 需要更多休息时间，避免过于紧凑 |

**与其他参数的联动**：
- `pace`（节奏）：group_type会自动调整默认节奏（亲子/老人→轻松，朋友→暴走）
- `travelers`（人数）：如果用户没有指定人数，根据group_type推断默认人数
- `style`（风格）：group_type会影响景点风格偏好

**当前逻辑**：
- `GROUP_PACE = {"亲子": "轻松", "老人": "轻松", "单人": "适中", "情侣": "适中", "家庭": "适中", "朋友": "暴走"}`
- 如果用户明确指定了pace，使用用户指定的pace
- 如果用户没有指定pace，根据group_type推断默认pace

**影响权重**：⭐⭐⭐⭐（高，影响节奏、景点选择、预算）

---

### 3.5 budget_level（预算档位）

**参数说明**：出行的预算档位，影响餐饮、住宿、交通的预算计算。

**取值范围**：经济/适中/舒适/奢华

**对规划的影响**：

| 取值 | 影响维度 | 具体影响 |
|------|----------|----------|
| **经济** | 餐饮预算 | 30元/人/顿 |
| | 住宿预算 | 150元/间/晚 |
| | 交通预算 | 30元/人/天 |
| | 景点选择 | 倾向免费景点、低价景点 |
| | 住宿推荐 | 青旅、经济型酒店、民宿 |
| | 餐饮推荐 | 小吃、快餐、平价餐厅 |
| **适中** | 餐饮预算 | 80元/人/顿 |
| | 住宿预算 | 400元/间/晚 |
| | 交通预算 | 60元/人/天 |
| | 景点选择 | 综合考虑，包括收费景点 |
| | 住宿推荐 | 中档酒店、连锁酒店 |
| | 餐饮推荐 | 中档餐厅、特色餐厅 |
| **舒适** | 餐饮预算 | 150元/人/顿 |
| | 住宿预算 | 800元/间/晚 |
| | 交通预算 | 120元/人/天 |
| | 景点选择 | 倾向高品质景点、VIP体验 |
| | 住宿推荐 | 高档酒店、精品酒店 |
| | 餐饮推荐 | 高档餐厅、网红餐厅 |
| **奢华** | 餐饮预算 | 300元/人/顿 |
| | 住宿预算 | 1500元/间/晚 |
| | 交通预算 | 200元/人/天 |
| | 景点选择 | 倾向顶级景点、私人定制体验 |
| | 住宿推荐 | 五星级酒店、奢华度假村 |
| | 餐饮推荐 | 米其林餐厅、顶级餐厅 |

**预算表**（`BUDGET_TABLE`）：
```python
BUDGET_TABLE = {
    "经济": {"food": 30, "hotel": 150, "transport": 30},
    "适中": {"food": 80, "hotel": 400, "transport": 60},
    "舒适": {"food": 150, "hotel": 800, "transport": 120},
    "奢华": {"food": 300, "hotel": 1500, "transport": 200},
}
```

**总预算计算**：
- 每天预算 = (餐饮预算 × 2顿 + 住宿预算 + 交通预算) × 人数
- 总预算 = 每天预算 × 天数
- 门票费用单独计算

**与其他参数的联动**：
- `travelers`（人数）：总预算 = 人均预算 × 人数
- `days`（天数）：总预算 = 每天预算 × 天数
- `group_type`（人群类型）：影响住宿房间数（如亲子可能需要家庭房）

**影响权重**：⭐⭐⭐⭐（高，主要影响预算计算和推荐档位）

### 3.6 pace（节奏）

**参数说明**：出行的节奏，影响每天景点数量和行程紧凑程度。

**取值范围**：轻松/适中/暴走

**对规划的影响**：

| 取值 | 影响维度 | 具体影响 |
|------|----------|----------|
| **轻松** | 每天点位数量 | 3个点位/天 |
| | 行程安排 | 行程宽松，有更多休息时间 |
| | 景点选择 | 倾向大景点、深度游览，避免来回跑 |
| | 适用人群 | 亲子、老人、度假型游客 |
| **适中** | 每天点位数量 | 4个点位/天 |
| | 行程安排 | 行程适中，既有景点游览，也有休息时间 |
| | 景点选择 | 综合考虑，经典景点+小众景点 |
| | 适用人群 | 大多数游客 |
| **暴走** | 每天点位数量 | 5个点位/天 |
| | 行程安排 | 行程紧凑，尽可能多游览景点 |
| | 景点选择 | 倾向多个小景点、打卡型景点 |
| | 适用人群 | 朋友、年轻游客、打卡型游客 |

**节奏配置**（`PACE_ITEMS`）：
```python
PACE_ITEMS = {"轻松": 3, "适中": 4, "暴走": 5}
```

**与其他参数的联动**：
- `group_type`（人群类型）：如果用户没有指定pace，根据group_type推断默认pace
  - 亲子/老人 → 轻松
  - 单人/情侣/家庭 → 适中
  - 朋友 → 暴走
- `days`（天数）：总景点数量 = 每天点位数量 × 天数
- `style`（风格）：影响景点选择，但不直接影响节奏

**当前逻辑**：
- 如果用户明确指定了pace，使用用户指定的pace
- 如果用户没有指定pace，但指定了group_type，根据group_type推断默认pace
- 如果用户既没有指定pace，也没有指定group_type，默认适中节奏

**影响权重**：⭐⭐⭐⭐（高，直接影响每天景点数量和行程紧凑程度）

---

### 3.7 style（旅行风格）

**参数说明**：旅行的风格偏好，影响景点选择。

**取值范围**：美食/人文/网红/小众/亲子/自然，可组合如"美食+人文"

**对规划的影响**：

| 取值 | 影响维度 | 具体影响 |
|------|----------|----------|
| **美食** | 景点选择 | 倾向美食街、特色餐厅、老字号、夜市 |
| | 辅助点位 | 增加美食推荐数量 |
| | 行程安排 | 午餐/晚餐时间安排特色餐厅 |
| **人文** | 景点选择 | 倾向博物馆、历史遗迹、文化景点、古建筑 |
| | 辅助点位 | 增加文化景点推荐 |
| | 行程安排 | 安排更多时间在文化景点深度游览 |
| **网红** | 景点选择 | 倾向网红打卡点、热门景点、拍照圣地 |
| | 辅助点位 | 增加网红餐厅、网红咖啡馆推荐 |
| | 行程安排 | 安排在最佳拍照时间游览 |
| **小众** | 景点选择 | 倾向小众景点、冷门景点、本地人去的地方 |
| | 辅助点位 | 增加小众餐厅、小众咖啡馆推荐 |
| | 行程安排 | 避免热门景点的高峰时段 |
| **亲子** | 景点选择 | 倾向亲子友好、游乐园、动物园、科普类景点 |
| | 辅助点位 | 增加亲子餐厅、亲子活动推荐 |
| | 行程安排 | 中午安排午休，避免过于紧凑 |
| **自然** | 景点选择 | 倾向自然风光、公园、山川湖海、森林公园 |
| | 辅助点位 | 增加自然景观推荐 |
| | 行程安排 | 安排更多时间在户外，注意天气和防晒 |

**组合风格**：
- 如"美食+人文"：同时考虑美食和人文景点
- 如"网红+小众"：在网红和小众之间平衡

**与其他参数的联动**：
- `group_type`（人群类型）：亲子group_type会倾向亲子风格
- `interests`（兴趣标签）：interests会进一步细化景点选择
- `must_include_poi`（必去景点）：必去景点优先，不受style影响

**当前逻辑**：
- style主要用于LLM优化时的景点筛选
- 规则引擎中style的影响相对较弱，主要依赖LLM优化

**影响权重**：⭐⭐⭐（中，主要影响景点选择）

---

### 3.8 traffic_mode（交通方式）

**参数说明**：出行的交通方式，影响路线规划和交通预算。

**取值范围**：自驾/公共交通/骑行/步行/混合

**对规划的影响**：

| 取值 | 影响维度 | 具体影响 |
|------|----------|----------|
| **自驾** | 路线规划 | 考虑停车场、自驾路线、高速费用 |
| | 景点选择 | 可以选择更远的景点，不受公共交通限制 |
| | 交通预算 | 油费+高速费+停车费 |
| | 行程安排 | 景点之间交通时间更短，可以安排更多景点 |
| **公共交通** | 路线规划 | 考虑地铁、公交、步行路线 |
| | 景点选择 | 倾向公共交通便利的景点 |
| | 交通预算 | 地铁+公交费用 |
| | 行程安排 | 景点之间交通时间更长，需要考虑换乘 |
| **骑行** | 路线规划 | 考虑自行车道、骑行路线 |
| | 景点选择 | 倾向骑行可达的景点，距离不宜过远 |
| | 交通预算 | 共享单车费用 |
| | 行程安排 | 景点之间距离适中，考虑体力 |
| **步行** | 路线规划 | 考虑步行路线、人行道 |
| | 景点选择 | 倾向步行可达的景点，距离较近 |
| | 交通预算 | 0 |
| | 行程安排 | 景点之间距离很近，适合citywalk |
| **混合** | 路线规划 | 根据景点距离灵活选择交通方式 |
| | 景点选择 | 综合考虑，不受单一交通方式限制 |
| | 交通预算 | 综合计算 |
| | 行程安排 | 灵活安排 |

**与其他参数的联动**：
- `budget_level`（预算）：影响交通预算计算
- `pace`（节奏）：交通方式影响每天可安排的景点数量
- `group_type`（人群类型）：亲子/老人可能更倾向自驾或公共交通

**当前逻辑**：
- traffic_mode主要用于路线规划和交通预算计算
- 规则引擎中traffic_mode的影响相对较弱

**影响权重**：⭐⭐⭐（中，主要影响路线规划和交通预算）

### 3.14 plan_strategy（规划策略）

**参数说明**：规划的策略，决定规划的算法流程。

**取值范围**：traditional（传统按天分配）/ spatial_temporal（先空间整体规划再时间拆分）

**对规划的影响**：

| 取值 | 影响维度 | 具体影响 |
|------|----------|----------|
| **traditional** | 规划流程 | 直接按天分配景点 |
| | 聚类切分 | 聚类后直接分配到天 |
| | 路线优化 | 相对较弱 |
| | 适用场景 | 短行程（1-3天）、单一城市 |
| **spatial_temporal** | 规划流程 | 先空间整体路线规划，再按时间拆分 |
| | 聚类切分 | 先规划整体路线，再拆分到天 |
| | 路线优化 | 更强，考虑出发点和返回点 |
| | 适用场景 | 长行程（3天以上）、跨城市/跨省 |

**与其他参数的联动**：
- `origin`（出发点）：两阶段规划时，出发点作为路线起点
- `return_point`（返回点）：两阶段规划时，返回点作为路线终点
- `days`（天数）：长行程更适合两阶段规划

**当前逻辑**：
- 默认使用traditional策略
- 用户可以通过plan_strategy参数指定策略
- 两阶段规划需要出发点和返回点效果更好

**影响权重**：⭐⭐⭐（中，决定规划的算法流程）

### 3.15 span_unit / span_value（时间跨度）

**参数说明**：原始时间跨度单位和数量，用于大时间跨度（月/年）的规划。

**取值范围**：
- `span_unit`：day/week/month/year
- `span_value`：数量

**对规划的影响**：

| 取值 | 影响维度 | 具体影响 |
|------|----------|----------|
| **day** | 时间跨度 | 以天为单位，直接使用days |
| **week** | 时间跨度 | 1周=7天，转换为days |
| **month** | 时间跨度 | 1个月=30天，生成月度分配摘要 |
| | 景点枚举 | 1个月规划当前省或临近省，2个月安排2个省 |
| | 规划结果 | 生成月度分配摘要，按省/月合理分配 |
| **year** | 时间跨度 | 1年=365天，生成年度分配摘要 |
| | 景点枚举 | 按省规划，哪个月是这个省比较好的出行时间就安排在哪个月 |
| | 规划结果 | 生成年度分配摘要，按省/月合理分配 |

**时间跨度收束**：
- 年/月/日维度的归一化与15天上限已在意图层完成
- 规划引擎按可支撑的区域数再收束一次

**与其他参数的联动**：
- `destination`（目的地）：大时间跨度时，按省规划
- `days`（天数）：span_unit和span_value转换为days

**当前逻辑**：
- `_build_long_span_summary(req, province)`生成大时间跨度摘要
- 月度分配：1个月规划当前省或临近省，2个月安排2个省
- 年度分配：按省规划，哪个月是这个省比较好的出行时间就安排在哪个月

**影响权重**：⭐⭐⭐（中，主要影响大时间跨度的规划）

## 4. 参数联动关系总结

### 4.1 高联动参数组

| 参数组 | 联动关系 | 影响 |
|--------|----------|------|
| **group_type + pace + travelers** | group_type影响默认pace和默认travelers | 人群类型决定节奏和人数的默认值 |
| **budget_level + travelers + days** | 总预算 = 人均预算 × 人数 × 天数 | 预算计算的核心公式 |
| **destination + days** | 目的地可支撑区域数收束天数 | 避免规划点不足或过于庞杂 |
| **style + interests** | interests是style的细化 | 共同影响景点选择 |
| **must_include_poi + exclude_poi** | 两者互斥，硬性约束 | 必须满足的景点约束 |
| **origin + return_point + plan_strategy** | 两阶段规划需要出发点和返回点 | 决定规划的算法流程 |

### 4.2 参数优先级

当参数之间存在冲突时，按以下优先级处理：

1. **硬性约束**（最高优先级）：must_include_poi、exclude_poi
2. **用户明确指定**：用户明确指定的参数值
3. **联动推断**：根据其他参数推断的默认值（如group_type推断pace和travelers）
4. **系统默认值**（最低优先级）：系统默认的参数值

## 6. 优化建议

### 6.1 当前参数使用的问题

1. **部分参数影响较弱**：style、interests、traffic_mode等参数在规则引擎中的影响较弱，主要依赖LLM优化
2. **参数联动不够充分**：部分参数之间的联动关系没有充分利用
3. **参数优先级不够清晰**：参数冲突时的优先级处理不够明确
4. **缺少参数验证**：部分参数值的合理性没有验证（如days与destination的匹配）

### 6.2 优化方向

1. **增强参数影响**：增强style、interests、traffic_mode等参数在规则引擎中的影响
2. **完善参数联动**：充分利用参数之间的联动关系，提升规划质量
3. **明确参数优先级**：明确参数冲突时的优先级处理
4. **增加参数验证**：验证参数值的合理性，避免不合理的规划结果
