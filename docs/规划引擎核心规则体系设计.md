# 规划引擎核心规则体系设计

> 文档版本：v1.1  
> 更新时间：2026-08-29  
> 适用范围：行程规划引擎的核心规则设计，包括无上限参数收束、人群影响、出行方式影响及灵活机制等

---

## 1. 文档概述

本文档详细设计行程规划引擎的核心规则体系，解决以下关键问题：

1. **无上限参数的兜底和收束**：时间、人数、预算这些参数可以无上限，需要划定最小值作为兜底，同时当值极大时需要策略做好收束，规则要闭环。
2. **人群参数对出行规划的影响点**：亲子、老人、情侣、单人、家庭、朋友等不同人群对规划的具体影响是什么，影响比例是多少，会不会影响主要景点规划。
3. **出行方式的影响规则**：公共交通（高铁、大巴、公交、地铁、打车、共享）和自驾对规划的影响，景点与景点之间的通行方式选择。
4. **出行方式影响的灵活机制**：出行方式对规划的影响不应该是硬性约束，而应该是灵活的、可调节的，根据场景判断影响强度（强/中/弱），可以影响也可以不影响。
5. **出行方式规划进行程的程度分级**：出行方式要不要规划进行程、规划到什么程度，也是一个影响很大的点，根据场景判断规划程度（详细规划/简要规划/不规划）。

**核心原则**：规则要闭环，既要兜底（最小值），也要收束（最大值），同时要明确影响点和影响比例；出行方式影响要灵活，根据场景动态调整影响强度和规划程度。

---

## 2. 无上限参数的兜底和收束规则

### 2.1 设计原则

无上限参数（时间、人数、预算）需要遵循以下设计原则：

1. **兜底原则**：划定最小值，确保参数不会过小导致规划无法进行
2. **收束原则**：划定最大值或收束策略，确保参数不会过大导致规划过于庞杂
3. **闭环原则**：从最小值到最大值形成完整的规则体系，每个区间都有明确的处理策略
4. **渐进原则**：参数值的变化对规划的影响应该是渐进的，而不是突变的

---

### 2.2 时间参数（days）的兜底和收束

#### 2.2.1 参数定义
- **参数名**：days
- **含义**：出行时间跨度（天）
- **原始输入**：用户可能输入任意天数，甚至以周/月/年为单位

#### 2.2.2 兜底规则（最小值）
- **最小天数**：1天
- **兜底逻辑**：
  - 如果用户输入 < 1天，默认设置为1天
  - 1天行程：单日游，不需要住宿，不需要考虑跨天交通
  - 1天行程安排：上午2个景点 + 午餐 + 下午2个景点 + 晚餐（根据节奏调整）

#### 2.2.3 收束规则（最大值）
- **最大天数**：15天（硬上限）
- **收束逻辑**：
  - 如果用户输入 > 15天，收束为15天
  - 超过15天的行程需要特殊处理（见大时间跨度规划）

#### 2.2.4 分区间处理策略

| 天数区间 | 规划策略 | 景点数量 | 住宿安排 | 聚类方式 |
|----------|----------|----------|----------|----------|
| **1天** | 单日游 | 3-5个景点 | 无住宿 | 1个聚类 |
| **2-3天** | 短途游 | 每天3-5个，总计6-15个 | 1-2晚住宿 | 2-3个聚类 |
| **4-7天** | 中途游 | 每天3-5个，总计12-35个 | 3-6晚住宿 | 4-7个聚类，可能跨城市 |
| **8-15天** | 长途游 | 每天2-4个，总计16-60个 | 7-14晚住宿 | 8-15个聚类，跨城市/跨省 |
| **>15天** | 收束为15天 | 同上 | 同上 | 同上 |

#### 2.2.5 时间跨度收束的闭环规则

```
用户输入天数
    ↓
是否 < 1天？ → 是 → 设置为1天（兜底）
    ↓ 否
是否 > 15天？ → 是 → 设置为15天（收束）
    ↓ 否
是否以周/月/年为单位？ → 是 → 转换为天数（周×7，月×30，年×365）
    ↓ 否
是否超过目的地可支撑的区域数？ → 是 → 收束为可支撑区域数
    ↓ 否
使用用户输入天数
```

#### 2.2.6 大时间跨度（月/年）的特殊处理

如果用户输入以月/年为单位：

| 时间单位 | 处理策略 | 规划粒度 |
|----------|----------|----------|
| **1个月** | 规划当前省或临近省，按周拆分 | 每周2-3个城市，每个城市2-3天 |
| **2个月** | 安排2个省，按月拆分 | 每个省1个月，按周拆分 |
| **3-6个月** | 安排3-6个省，按月拆分 | 每个省1个月，按周拆分 |
| **>6个月** | 收束为6个月，安排6个省 | 每个省1个月，按周拆分 |
| **1年** | 按省规划，哪个月是这个省的最佳出行时间就安排在哪个月 | 每月1个省，按最佳季节分配 |

**月度分配逻辑**：
- 每个省有最佳出行季节（如云南最佳是春季，东北最佳是冬季）
- 按最佳季节分配省份到月份
- 避免在同一月份安排多个省

### 2.3 人数参数（travelers）的兜底和收束

#### 2.3.1 参数定义
- **参数名**：travelers
- **含义**：出行人数
- **原始输入**：用户可能输入任意人数

#### 2.3.2 兜底规则（最小值）
- **最小人数**：1人
- **兜底逻辑**：
  - 如果用户输入 < 1人，默认设置为1人
  - 1人出行：单人游，住宿按1间房计算，餐饮按1人计算

#### 2.3.3 收束规则（最大值）
- **最大人数**：99人（硬上限）
- **收束逻辑**：
  - 如果用户输入 > 99人，收束为99人
  - 超过20人的团体需要特殊处理（见团体出行规划）

#### 2.3.4 分区间处理策略

| 人数区间 | 规划策略 | 住宿安排 | 餐饮安排 | 景点选择 |
|----------|----------|----------|----------|----------|
| **1人** | 单人游 | 1间单人间/青旅 | 单人餐 | 可以更小众、更个性化 |
| **2人** | 双人游 | 1间标准间 | 双人餐 | 可以更浪漫、更精致 |
| **3-4人** | 小团体 | 1-2间房 | 小桌餐 | 综合考虑，经典景点为主 |
| **5-10人** | 中团体 | 3-5间房 | 大桌餐/分餐 | 需要预约团体票，经典景点为主 |
| **11-20人** | 大团体 | 6-10间房 | 团体餐 | 需要预约团体票，避免过于分散 |
| **>20人** | 超大团体 | 收束为20人处理 | 团体餐 | 需要特殊安排，避免过于分散 |

#### 2.3.5 人数对预算计算的影响

- **住宿**：
  - 1-2人：1间房
  - 3-4人：2间房（或1间家庭房）
  - 5-8人：3-4间房
  - 以此类推，每2人1间房（亲子/家庭可能需要家庭房）

- **餐饮**：
  - 按实际人数计算
  - 团体可能有团体折扣（10人以上9折，20人以上8折）

- **交通**：
  - 按实际人数计算
  - 团体可能有团体票优惠

#### 2.3.6 人数收束的闭环规则

```
用户输入人数
    ↓
是否 < 1人？ → 是 → 设置为1人（兜底）
    ↓ 否
是否 > 99人？ → 是 → 设置为99人（收束）
    ↓ 否
用户是否明确指定group_type？ → 是 → 根据group_type推断默认人数（如未指定人数）
    ↓ 否
使用用户输入人数
```

### 2.4 预算参数（budget_level）的兜底和收束

#### 2.4.1 参数定义
- **参数名**：budget_level
- **含义**：预算档位（经济/适中/舒适/奢华）
- **原始输入**：用户可能输入具体金额，也可能输入档位

#### 2.4.2 兜底规则（最小值）
- **最低档位**：经济
- **兜底逻辑**：
  - 如果用户输入低于经济档，默认设置为经济档
  - 经济档：餐饮30元/人/顿，住宿150元/间/晚，交通30元/人/天

#### 2.4.3 收束规则（最大值）
- **最高档位**：奢华
- **收束逻辑**：
  - 如果用户输入高于奢华档，收束为奢华档
  - 奢华档：餐饮300元/人/顿，住宿1500元/间/晚，交通200元/人/天

#### 2.4.4 分档位处理策略

| 预算档位 | 餐饮预算 | 住宿预算 | 交通预算 | 景点选择 | 推荐类型 |
|----------|----------|----------|----------|----------|----------|
| **经济** | 30元/人/顿 | 150元/间/晚 | 30元/人/天 | 免费/低价景点 | 青旅、小吃、公共交通 |
| **适中** | 80元/人/顿 | 400元/间/晚 | 60元/人/天 | 综合考虑 | 连锁酒店、特色餐厅、地铁 |
| **舒适** | 150元/人/顿 | 800元/间/晚 | 120元/人/天 | 高品质景点 | 精品酒店、高档餐厅、打车 |
| **奢华** | 300元/人/顿 | 1500元/间/晚 | 200元/人/天 | 顶级景点/VIP | 五星级酒店、米其林、专车 |

#### 2.4.5 具体金额到档位的映射

如果用户输入具体金额（如"人均2000元"），需要映射到档位：

| 人均总预算（3天） | 映射档位 | 说明 |
|-------------------|----------|------|
| < 500元 | 经济 | 穷游 |
| 500-1500元 | 适中 | 普通游 |
| 1500-3000元 | 舒适 | 品质游 |
| > 3000元 | 奢华 | 豪华游 |

#### 2.4.6 预算收束的闭环规则

```
用户输入预算
    ↓
是具体金额还是档位？ → 具体金额 → 映射到档位
    ↓ 档位
是否低于经济档？ → 是 → 设置为经济档（兜底）
    ↓ 否
是否高于奢华档？ → 是 → 设置为奢华档（收束）
    ↓ 否
使用用户输入档位
```

## 3. 人群参数对出行规划的影响点

### 3.1 设计原则

人群参数（group_type）对规划的影响应该遵循以下原则：

1. **主要景点优先**：无论什么人群，目标城市的主要景点（名胜古迹、标志性景点）都应该优先规划，人群参数只影响辅助景点和行程安排
2. **影响比例明确**：人群参数对规划的影响应该有明确的比例，而不是完全替代主要景点
3. **影响点清晰**：人群参数应该影响明确的维度（景点选择、节奏、餐饮、住宿、交通），而不是模糊的"适合"
4. **渐进影响**：人群参数的影响应该是渐进的，而不是非此即彼

---

### 3.2 人群参数的影响维度

人群参数影响以下6个维度，每个维度的影响比例不同：

| 影响维度 | 影响程度 | 说明 |
|----------|----------|------|
| **主要景点选择** | 0-10% | 主要景点基本不受影响，所有人群都应该去 |
| **辅助景点选择** | 30-50% | 辅助景点受人群影响较大，如亲子选游乐园，情侣选浪漫景点 |
| **节奏安排** | 20-30% | 亲子/老人节奏慢，朋友节奏快 |
| **餐饮推荐** | 30-50% | 亲子选亲子餐厅，情侣选浪漫餐厅 |
| **住宿推荐** | 20-30% | 亲子选亲子酒店，情侣选情侣酒店 |
| **交通方式** | 10-20% | 亲子/老人更倾向自驾或打车 |

**核心原则**：主要景点（名胜古迹、标志性景点）占行程的70-90%，人群相关的辅助景点占10-30%。

---

### 3.3 各人群类型的详细影响

#### 3.3.1 单人游

**影响点**：
- **主要景点**：100%保留，所有主要景点都可以去
- **辅助景点**：可以选择更小众、更个性化的景点（如独立书店、小众咖啡馆、艺术展览）
- **节奏**：适中节奏，每天4个点位
- **餐饮**：可以选择单人友好的餐厅（如一人食、小吃、快餐）
- **住宿**：单人间、青旅、经济型酒店
- **交通**：公共交通为主，灵活自由

**影响比例**：
- 主要景点：90%
- 辅助景点（小众/个性化）：10%
- 节奏：适中
- 餐饮：单人友好
- 住宿：经济型

**注意事项**：
- 单人游不应该只规划小众景点，主要景点仍然是核心
- 单人游的优势是灵活自由，可以随时调整行程

---

#### 3.3.2 情侣游

**影响点**：
- **主要景点**：90%保留，所有主要景点都应该去
- **辅助景点**：增加浪漫氛围的景点（如夜景、摩天轮、湖边散步、浪漫咖啡馆、情侣主题餐厅）
- **节奏**：适中节奏，每天4个点位，可以更悠闲
- **餐饮**：增加浪漫餐厅推荐（如烛光晚餐、景观餐厅、网红餐厅）
- **住宿**：情侣酒店、精品酒店、浪漫主题房
- **交通**：可以选择更浪漫的交通方式（如游船、马车、观光巴士）

**影响比例**：
- 主要景点：80%
- 辅助景点（浪漫/网红）：20%
- 节奏：适中偏慢
- 餐饮：浪漫餐厅占30%
- 住宿：精品/情侣酒店

**注意事项**：
- **关键问题**：浪漫景点不应该影响主要景点的规划，主要景点（如故宫、长城）仍然是核心
- 浪漫景点应该作为辅助，穿插在主要景点之间（如晚上去看夜景，下午去浪漫咖啡馆）
- 不要把所有时间都花在浪漫景点上，否则会错过目标城市的主要景点

**浪漫景点的穿插策略**：
- 上午：主要景点（如故宫）
- 下午：主要景点 + 浪漫咖啡馆（如景山公园看故宫全景 + 附近咖啡馆）
- 晚上：浪漫景点（如什刹海夜景、南锣鼓巷漫步）
- 这样既保证了主要景点，又增加了浪漫氛围

---

#### 3.3.3 亲子游

**影响点**：
- **主要景点**：80%保留，大部分主要景点都应该去，但需要考虑亲子友好性
  - **可以去的名胜古迹**：故宫（有儿童讲解）、长城（缆车上下）、颐和园（游船）、天坛（开阔）
  - **需要调整的名胜古迹**：过于陡峭的山路（如华山）、过于枯燥的博物馆（如纯文字展览）
- **辅助景点**：增加亲子友好景点（如游乐园、动物园、海洋馆、科技馆、儿童博物馆、亲子主题乐园）
- **节奏**：轻松节奏，每天3个点位，中午需要午休
- **餐饮**：亲子餐厅、儿童友好餐厅、有儿童餐的餐厅
- **住宿**：亲子酒店、家庭房、有儿童设施的酒店
- **交通**：自驾或打车为主，减少换乘，避免长时间步行

**影响比例**：
- 主要景点（亲子友好的名胜古迹）：60%
- 辅助景点（亲子/游乐园）：40%
- 节奏：轻松，中午午休
- 餐饮：亲子餐厅占40%
- 住宿：亲子酒店/家庭房

**注意事项**：
- **关键问题**：亲子游不是只去游乐园，目标城市的名胜古迹仍然是核心，但需要选择亲子友好的名胜古迹
- 例如去北京，亲子游仍然应该去故宫、长城、颐和园，但需要：
  - 故宫：租儿童讲解器，走中轴线，不要走太多偏殿
  - 长城：选择慕田峪（有缆车，人少），不要选择八达岭（人多，陡峭）
  - 颐和园：乘船游览，不要全程步行
- 同时增加1-2个亲子景点（如北京动物园、中国科技馆、欢乐谷）

**亲子友好的名胜古迹筛选标准**：
- 有儿童讲解或互动设施
- 有缆车/游船等代步工具
- 场地开阔，不会过于拥挤
- 有休息区和卫生间
- 不会过于陡峭或需要大量体力

---

#### 3.3.4 家庭游

**影响点**：
- **主要景点**：90%保留，所有主要景点都应该去，需要考虑全家友好性
- **辅助景点**：增加全家友好景点（如公园、文化景点、经典景点）
- **节奏**：适中节奏，每天4个点位
- **餐饮**：全家友好餐厅（如中餐、家常菜、有包间的餐厅）
- **住宿**：家庭房、套房、连通房
- **交通**：根据家庭构成选择，有老人小孩倾向自驾或打车

**影响比例**：
- 主要景点：85%
- 辅助景点（全家友好）：15%
- 节奏：适中
- 餐饮：全家友好
- 住宿：家庭房/套房

**注意事项**：
- 家庭游通常是2大1小或2大2小，需要考虑不同年龄段的需求
- 主要景点仍然是核心，辅助景点作为补充

---

#### 3.3.5 朋友游

**影响点**：
- **主要景点**：80%保留，主要景点仍然要去，但可以更灵活
- **辅助景点**：增加网红打卡、夜生活、美食、购物景点
- **节奏**：暴走节奏，每天5个点位，可以更紧凑
- **餐饮**：网红餐厅、特色小吃、夜市、美食街
- **住宿**：青旅、经济型酒店、民宿（可以一起住）
- **交通**：公共交通为主，可以尝试当地特色交通

**影响比例**：
- 主要景点：70%
- 辅助景点（网红/夜生活/美食）：30%
- 节奏：暴走
- 餐饮：网红/特色占50%
- 住宿：经济型/青旅/民宿

**注意事项**：
- 朋友游可以更灵活，主要景点和网红景点可以各占一半
- 夜生活和美食是朋友游的重点，可以安排更多时间

---

#### 3.3.6 老人游

**影响点**：
- **主要景点**：95%保留，老人游的核心就是看名胜古迹，主要景点几乎全部保留
- **辅助景点**：增加平缓、文化类景点（如公园、寺庙、历史文化街区）
- **节奏**：轻松节奏，每天3个点位，需要更多休息时间
- **餐饮**：清淡、软烂、易消化的餐厅，避免辛辣刺激
- **住宿**：舒适型酒店、低楼层房间、有电梯、靠近医院
- **交通**：自驾或打车为主，减少步行和换乘，避免高峰期

**影响比例**：
- 主要景点（名胜古迹）：90%
- 辅助景点（平缓/文化）：10%
- 节奏：轻松，多休息
- 餐饮：清淡/易消化
- 住宿：舒适型/低楼层/有电梯

**注意事项**：
- **关键问题**：老人游不是只去活动量小的景点，目标城市的名胜古迹仍然是核心，甚至是首要目标
- 例如去北京，老人游仍然应该去故宫、长城、颐和园、天坛，但需要：
  - 故宫：租轮椅，走中轴线，多休息
  - 长城：选择慕田峪（有缆车，平缓），不要选择八达岭（人多，陡峭）
  - 颐和园：乘船游览，不要全程步行
  - 天坛：走中轴线，不要走太多偏殿
- 辅助景点可以选择平缓的公园（如北海公园、景山公园），但不要替代主要景点

**老人友好的名胜古迹筛选标准**：
- 有轮椅通道或无障碍设施
- 有缆车/游船等代步工具
- 场地开阔，不会过于拥挤
- 有休息区和卫生间
- 不会过于陡峭或需要大量体力
- 有遮阳避雨的地方

    ↓
确定主要景点池（目标城市的名胜古迹、标志性景点）
    ↓

## 4. 出行方式的影响规则

### 4.1 设计原则

出行方式（traffic_mode）对规划的影响应该遵循以下原则：

1. **大交通和市内交通分离**：大交通（高铁、飞机、大巴）和市内交通（地铁、公交、打车、自驾）要分开考虑
2. **目的地适配性**：自驾需要考虑目的地适不适合开车（如城市中心停车难、景区交通管制）
3. **景点间通行方式选择**：景点与景点之间，根据距离、时间、费用、便利性选择最合适的通行方式
4. **公共交通的多样性**：公共交通包括高铁、大巴、公交、地铁、打车、共享单车等，要根据场景选择

---

### 4.2 大交通方式的影响

#### 4.2.1 大交通方式分类

| 大交通方式 | 适用场景 | 优点 | 缺点 |
|------------|----------|------|------|
| **高铁** | 中短途（1-4小时），城市间 | 准时、舒适、快捷 | 费用较高，需要提前订票 |
| **飞机** | 长途（>4小时），跨省/跨国 | 快捷 | 费用高，受天气影响，需要提前到机场 |
| **大巴** | 中短途，高铁不方便的地方 | 费用低，班次多 | 慢，不舒适，受交通影响 |
| **自驾** | 中短途，灵活自由 | 灵活自由，行李方便 | 疲劳，停车难，费用高（油费+过路费+停车费） |

#### 4.2.2 大交通对规划的影响

- **第一天行程**：
  - 高铁/飞机：到达时间决定第一天行程开始时间，需要考虑从车站/机场到酒店的交通
  - 自驾：出发时间灵活，可以早上出发，中午到达，下午开始行程
- **最后一天行程**：
  - 高铁/飞机：返程时间决定最后一天行程结束时间，需要考虑从酒店到车站/机场的交通
  - 自驾：返程时间灵活，可以下午结束行程，晚上返程
- **住宿安排**：
  - 高铁/飞机：住宿安排在车站/机场附近或市中心
  - 自驾：住宿需要有停车场

---

### 4.3 市内交通方式的影响

#### 4.3.1 市内交通方式分类

| 市内交通方式 | 适用场景 | 优点 | 缺点 |
|--------------|----------|------|------|
| **地铁** | 大城市，景点之间距离较远 | 快捷、准时、便宜 | 高峰期拥挤，需要换乘 |
| **公交** | 地铁不方便的地方 | 便宜、覆盖广 | 慢、不准时、需要换乘 |
| **打车** | 短途、携带行李、老人小孩 | 快捷、方便、门到门 | 费用高，高峰期难打车 |
| **共享单车** | 短途（1-3公里），天气好 | 灵活、便宜、锻炼身体 | 受天气影响，需要停车点 |
| **步行** | 超短途（<1公里），景点密集区 | 免费、自由、可以逛 | 慢、累、受天气影响 |
| **自驾** | 景点分散、公共交通不方便 | 灵活、自由、行李方便 | 停车难、费用高、疲劳 |

#### 4.3.2 市内交通对规划的影响

- **景点选择**：
  - 公共交通：优先选择公共交通便利的景点（地铁沿线、公交直达）
  - 自驾：可以选择公共交通不方便的景点（郊区、山区）
- **景点顺序**：
  - 公共交通：按地铁/公交线路排序，减少换乘
  - 自驾：按路线最优排序，考虑停车场位置
- **每天景点数量**：
  - 公共交通：景点之间交通时间长，每天景点数量适当减少
  - 自驾：景点之间交通时间短，每天景点数量可以适当增加
- **餐饮安排**：
  - 公共交通：午餐安排在景点附近，不需要专门开车去餐厅
  - 自驾：可以开车去更远的特色餐厅

---

### 4.4 景点间通行方式的选择规则

#### 4.4.1 选择维度

景点与景点之间选择通行方式，需要考虑以下5个维度：

| 维度 | 权重 | 说明 |
|------|------|------|
| **距离** | 40% | 距离是最主要的决定因素 |
| **时间** | 25% | 可用时间决定选择哪种交通方式 |
| **费用** | 15% | 预算档位影响交通方式选择 |
| **便利性** | 15% | 携带行李、老人小孩、天气等影响便利性 |
| **体验性** | 5% | 特色交通方式（如游船、缆车）可以增加体验 |

#### 4.4.2 按距离选择通行方式

| 景点间距离 | 推荐通行方式 | 备选通行方式 | 说明 |
|------------|--------------|--------------|------|
| **< 500米** | 步行 | - | 超短途，步行最方便 |
| **500米-2公里** | 共享单车 | 步行 | 短途，骑行快捷方便 |
| **2-5公里** | 打车/地铁 | 公交 | 中短途，打车或地铁都可以 |
| **5-15公里** | 地铁/打车 | 公交 | 中长途，地铁优先，打车备选 |
| **15-30公里** | 地铁/打车 | 自驾 | 长途，地铁或打车，自驾备选 |
| **> 30公里** | 自驾/高铁 | 打车 | 超长途，自驾或高铁，打车费用高 |

#### 4.4.3 按人群选择通行方式

| 人群类型 | 优先通行方式 | 说明 |
|----------|--------------|------|
| **单人** | 公共交通（地铁/公交） | 灵活自由，费用低 |
| **情侣** | 地铁/打车/特色交通 | 可以尝试浪漫的特色交通（如游船） |
| **亲子** | 自驾/打车 | 减少换乘，避免长时间步行，携带儿童用品方便 |
| **家庭** | 自驾/打车 | 人多，公共交通不方便，自驾或打车更舒适 |
| **朋友** | 公共交通（地铁/公交） | 人多可以一起坐地铁，费用低，体验当地生活 |
| **老人** | 自驾/打车 | 减少步行和换乘，避免高峰期，舒适安全 |

#### 4.4.4 按预算选择通行方式

| 预算档位 | 优先通行方式 | 说明 |
|----------|--------------|------|
| **经济** | 公共交通（地铁/公交） | 费用最低 |
| **适中** | 地铁为主，打车为辅 | 综合考虑时间和费用 |
| **舒适** | 打车为主，地铁为辅 | 舒适快捷，费用适中 |
| **奢华** | 专车/包车 | 门到门服务，舒适奢华 |

#### 4.4.5 特殊场景的通行方式选择

| 特殊场景 | 推荐通行方式 | 说明 |
|----------|--------------|------|
| **携带行李** | 打车/自驾 | 避免搬运行李换乘 |
| **下雨天** | 打车/地铁 | 避免骑行和步行 |
| **高峰期** | 地铁 | 避免打车堵车 |
| **景点密集区** | 步行/共享单车 | 距离近，步行可以逛 |
| **郊区景点** | 自驾/打车 | 公共交通不方便 |
| **山区景点** | 自驾/景区大巴 | 公共交通不方便，需要爬山 |
| **夜间出行** | 打车 | 公共交通可能停运，安全考虑 |

---

### 4.5 自驾的特殊规则

#### 4.5.1 目的地适配性判断

自驾需要考虑目的地适不适合开车：

| 目的地类型 | 是否适合自驾 | 说明 |
|------------|--------------|------|
| **大城市中心** | 不太适合 | 停车难、堵车、限行、费用高 |
| **郊区/山区** | 适合 | 公共交通不方便，自驾灵活 |
| **多景点跨城** | 适合 | 灵活自由，行李方便 |
| **单城市深度游** | 不太适合 | 市内公共交通更方便，停车难 |
| **亲子/老人游** | 适合 | 减少换乘，舒适安全 |
| **朋友游** | 可以考虑 | 人多分摊费用，灵活自由 |

#### 4.5.2 自驾对规划的影响

- **景点选择**：
  - 可以选择公共交通不方便的景点（郊区、山区）
  - 优先选择有停车场的景点
- **景点顺序**：
  - 按路线最优排序，考虑停车场位置
  - 避免在城市中心频繁开车（堵车、停车难）
- **每天景点数量**：
  - 景点之间交通时间短，每天景点数量可以适当增加
  - 但需要考虑驾驶疲劳，不要安排过多
- **餐饮安排**：
  - 可以开车去更远的特色餐厅
  - 优先选择有停车场的餐厅
- **住宿安排**：
  - 必须选择有停车场的酒店
  - 可以选择市郊的酒店（价格便宜，停车方便）

#### 4.5.3 自驾的注意事项

- **驾驶时间**：每天驾驶时间不超过4小时，避免疲劳驾驶
- **停车费用**：大城市停车费用高，需要计入预算
- **限行政策**：大城市可能有限行政策，需要提前了解
- **景区交通管制**：部分景区可能有交通管制，需要停在景区外换乘
- **油费/过路费**：需要计入预算
- **租车/还车**：如果是租车，需要考虑租车/还车时间和地点

### 4.6 出行方式影响的闭环规则

```
用户输入traffic_mode
    ↓
判断是大交通还是市内交通
    ↓
大交通：
    - 根据距离和时间选择高铁/飞机/大巴/自驾

    - 影响住宿选择（车站/机场附近 or 有停车场）
    ↓
市内交通：
    - 根据人群、预算、距离选择地铁/公交/打车/骑行/步行/自驾
    - 影响景点选择（公共交通便利 or 有停车场）
    - 影响景点顺序（按交通线路 or 按路线最优）
    - 影响每天景点数量（交通时间长则减少，交通时间短则增加）
    ↓

    - 根据预算（经济优先公共交通，奢华优先专车）
    - 根据特殊场景（携带行李、下雨天、高峰期、景点密集区等）
    ↓
生成最终行程和通行建议
```

### 4.7 出行方式影响的灵活机制

#### 4.7.1 设计理念

出行方式对规划的影响不应该是硬性约束，而应该是**灵活的、可调节的**。在某些场景下，出行方式对规划的影响很大；在另一些场景下，出行方式对规划的影响很小，甚至可以忽略。

**核心原则**：
1. **影响强度分级**：出行方式对规划的影响分为强、中、弱三个等级
2. **场景驱动**：根据具体场景（人群、目的地、景点分布、预算）判断影响强度
3. **灵活应用**：根据影响强度决定是否应用出行方式的影响规则
4. **用户优先**：用户明确指定的出行方式优先，但影响强度仍需根据场景判断

---

#### 4.7.2 影响强度分级

| 影响强度 | 说明 | 应用规则 | 典型场景 |
|----------|------|----------|----------|
| **强影响** | 出行方式显著影响规划结果 | 完整应用出行方式的所有影响规则 | 亲子游、老人游、郊区景点、跨城游、自驾 |
| **中影响** | 出行方式部分影响规划结果 | 应用部分影响规则（如景点顺序、通行建议），但不影响景点选择 | 朋友游、家庭游、混合目的地、公共交通 |
| **弱影响** | 出行方式对规划结果影响很小 | 仅提供通行建议，不影响景点选择和行程安排 | 单人游、情侣游、市中心景点密集区、1天短途游 |

---

#### 4.7.3 影响强度判断规则

影响强度由以下5个维度综合判断，每个维度有不同的权重：

| 判断维度 | 权重 | 强影响条件 | 中影响条件 | 弱影响条件 |
|----------|------|------------|------------|------------|
| **人群类型** | 30% | 亲子、老人 | 家庭、朋友 | 单人、情侣 |
| **目的地类型** | 25% | 郊区/山区/跨城 | 混合（市中心+郊区） | 纯市中心 |
| **景点分布** | 20% | 景点分散（距离>5公里） | 景点中等分散（2-5公里） | 景点密集（<2公里） |
| **出行天数** | 15% | >5天 | 3-5天 | 1-2天 |
| **预算档位** | 10% | 舒适/奢华 | 适中 | 经济 |

**综合判断公式**：
```
影响强度得分 = 人群类型得分×30% + 目的地类型得分×25% + 景点分布得分×20% + 出行天数得分×15% + 预算档位得分×10%

强影响：得分 >= 70分
中影响：40分 <= 得分 < 70分
弱影响：得分 < 40分
```

**各维度得分**：
- 人群类型：亲子/老人=100分，家庭/朋友=60分，单人/情侣=20分
- 目的地类型：郊区/山区/跨城=100分，混合=60分，纯市中心=20分
- 景点分布：分散=100分，中等分散=60分，密集=20分
- 出行天数：>5天=100分，3-5天=60分，1-2天=20分
- 预算档位：舒适/奢华=100分，适中=60分，经济=20分

---

#### 4.7.4 不同影响强度下的应用规则

##### 强影响场景

**应用规则**：完整应用出行方式的所有影响规则

| 影响维度 | 应用规则 |
|----------|----------|
| **景点选择** | 优先选择符合出行方式的景点（公共交通便利 or 有停车场） |
| **景点顺序** | 按出行方式优化景点顺序（按交通线路 or 按路线最优） |
| **每天景点数量** | 根据出行方式调整（公共交通时间长则减少，自驾时间短则增加） |
| **餐饮安排** | 根据出行方式选择餐厅（公共交通选景点附近，自驾可选更远餐厅） |
| **住宿安排** | 根据出行方式选择住宿（车站/机场附近 or 有停车场） |
| **通行建议** | 提供详细的景点间通行方式建议 |

**典型场景示例**：
- 亲子游北京5天，自驾：景点选择优先有停车场的，景点顺序按路线最优，住宿必须有停车场
- 老人游西安3天，公共交通：景点选择优先地铁沿线，景点顺序按地铁线路，每天景点数量适当减少

---

##### 中影响场景

#### 4.7.5 用户指定出行方式的处理

如果用户明确指定了出行方式，需要特殊处理：

| 用户指定情况 | 处理策略 |
|--------------|----------|
| **用户明确指定，且场景匹配** | 按用户指定的出行方式应用，影响强度按场景判断 |
| **用户明确指定，但场景不匹配** | 按用户指定的出行方式应用，但在回复中提示可能的不便（如"市中心停车较难，建议公共交通"） |
| **用户未指定** | 根据场景自动判断最优出行方式和影响强度 |

**场景不匹配的示例**：
- 用户指定自驾，但目的地是市中心景点密集区：提示"市中心停车较难，部分景点建议公共交通"
- 用户指定公共交通，但目的地是郊区山区：提示"郊区公共交通不太方便，部分景点建议打车或自驾"

#### 4.7.6 影响强度的动态调整

| 调整触发条件 | 调整方向 | 说明 |

| 用户反馈"景点太少" | 降低影响强度 | 减少出行方式对景点数量的限制 |
| 用户反馈"交通不方便" | 提高影响强度 | 增加出行方式对景点选择和顺序的影响 |
| 用户添加必去景点（交通不便） | 降低影响强度 | 必去景点优先，出行方式影响让位于必去景点 |
| 目的地变更（从市中心改为郊区） | 提高影响强度 | 目的地类型变化，影响强度相应调整 |

### 4.8 出行方式规划进行程的程度分级

#### 4.8.1 设计理念

出行方式要不要规划进行程、规划到什么程度，也是一个影响很大的点。在某些场景下，需要详细规划每个景点之间的具体交通方式、时间、费用；在另一些场景下，只需要提供大致建议即可，甚至完全不规划。

**核心原则**：
1. **规划程度分级**：出行方式规划进行程的程度分为详细规划、简要规划、不规划三个等级
2. **场景驱动**：根据具体场景（人群、目的地、出行方式、用户需求）判断规划程度
3. **与影响强度联动**：规划程度与影响强度（强/中/弱）相关但不完全等同
4. **用户优先**：用户明确要求详细规划时，按用户要求执行

---

#### 4.8.2 规划程度分级

| 规划程度 | 说明 | 行程中体现 | 典型场景 |
|----------|------|------------|----------|
| **详细规划** | 每个景点之间的交通方式、时间、费用都详细规划 | 行程中明确标注"地铁2号线，约20分钟，4元" | 亲子游、老人游、首次到访、公共交通、跨城游 |
| **简要规划** | 仅提供大致的交通方式建议，不详细到时间和费用 | 行程中标注"建议地铁/打车"，不标注具体时间和费用 | 朋友游、家庭游、混合出行方式、重复到访 |
| **不规划** | 完全不规划交通方式，仅提供景点和时间安排 | 行程中不体现交通方式，用户自行安排 | 单人游、情侣游、市中心景点密集区、自驾、1天短途游 |

---

#### 4.8.3 规划程度判断规则

规划程度由以下4个维度综合判断，每个维度有不同的权重：

| 判断维度 | 权重 | 详细规划条件 | 简要规划条件 | 不规划条件 |
|----------|------|--------------|--------------|------------|
| **人群类型** | 30% | 亲子、老人 | 家庭、朋友 | 单人、情侣 |
| **出行方式** | 30% | 公共交通 | 混合 | 自驾 |
| **目的地类型** | 25% | 郊区/山区/跨城 | 混合 | 纯市中心 |
| **出行天数** | 15% | >5天 | 3-5天 | 1-2天 |

**综合判断公式**：
```
规划程度得分 = 人群类型得分×30% + 出行方式得分×30% + 目的地类型得分×25% + 出行天数得分×15%

详细规划：得分 >= 70分
简要规划：40分 <= 得分 < 70分
不规划：得分 < 40分
```

**各维度得分**：
- 人群类型：亲子/老人=100分，家庭/朋友=60分，单人/情侣=20分
- 出行方式：公共交通=100分，混合=60分，自驾=20分
- 目的地类型：郊区/山区/跨城=100分，混合=60分，纯市中心=20分
- 出行天数：>5天=100分，3-5天=60分，1-2天=20分

---

#### 4.8.4 不同规划程度下的行程体现

##### 详细规划

**行程中体现**：
- 每个景点之间明确标注交通方式、时间、费用
- 示例："故宫 → 景山公园：步行，约10分钟，免费"
- 示例："颐和园 → 圆明园：地铁4号线，约15分钟，3元"
- 示例："市区 → 慕田峪长城：自驾，约1.5小时，油费+过路费约80元"

**详细规划的内容**：
1. **交通方式**：明确标注步行/骑行/地铁/公交/打车/自驾/高铁等
2. **时间预估**：预估交通所需时间（分钟/小时）
3. **费用预估**：预估交通费用（元）
4. **换乘提示**：如果需要换乘，标注换乘站点和线路
5. **注意事项**：特殊提示（如"地铁站出口即到"、"需要提前购票"）

**典型场景**：
- 亲子游北京5天，公共交通：每个景点之间详细标注地铁线路、时间、费用
- 老人游西安3天，公共交通：每个景点之间详细标注地铁/打车、时间、费用
- 首次到访上海4天，公共交通：每个景点之间详细标注地铁线路、时间、费用

---

##### 简要规划

**行程中体现**：
- 仅提供大致的交通方式建议，不详细到时间和费用
- 示例："故宫 → 景山公园：建议步行"
- 示例："颐和园 → 圆明园：建议地铁或打车"
- 示例："市区 → 慕田峪长城：建议自驾或景区大巴"

**简要规划的内容**：
1. **交通方式建议**：推荐1-2种交通方式
2. **不标注时间和费用**：仅提供方式建议，用户自行查询时间和费用
3. **特殊提示**：重要提示（如"郊区景点建议自驾"）

**典型场景**：
- 朋友游成都3天，混合出行方式：仅提供交通方式建议
- 家庭游杭州4天，混合出行方式：仅提供交通方式建议
- 重复到访广州3天，混合出行方式：仅提供交通方式建议

---

##### 不规划

**行程中体现**：
- 完全不规划交通方式，仅提供景点和时间安排
- 行程中不体现任何交通方式信息
- 用户自行安排交通

**不规划的内容**：
1. **仅景点和时间**：行程中只有景点名称、时间安排、介绍
2. **不体现交通方式**：完全不标注交通方式
3. **用户自行安排**：交通完全由用户自行决定

**典型场景**：
- 单人游成都2天，自驾：不规划交通，用户自行开车
- 情侣游厦门3天，市中心景点密集区：不规划交通，用户自行步行/骑行
- 1天短途游，市中心景点密集区：不规划交通，用户自行安排

#### 4.8.5 规划程度与影响强度的联动

规划程度与影响强度（强/中/弱）相关但不完全等同，两者的联动关系如下：

| 影响强度 | 规划程度 | 说明 |
|----------|----------|------|
| **强影响** | 通常详细规划 | 强影响场景下，出行方式显著影响规划，通常需要详细规划交通 |
| **中影响** | 通常简要规划 | 中影响场景下，出行方式部分影响规划，通常简要规划交通即可 |
| **弱影响** | 通常不规划 | 弱影响场景下，出行方式对规划影响很小，通常不需要规划交通 |

**但也有例外**：
- 强影响但自驾：影响强度强（如亲子游郊区），但规划程度可能是不规划（因为自驾用户自行安排）
- 弱影响但公共交通：影响强度弱（如单人游市中心），但用户可能要求详细规划（首次到访）

**判断优先级**：
1. 用户明确要求 > 场景自动判断
2. 规划程度判断 > 影响强度判断（规划程度更直接影响行程体现）
3. 两者综合考虑，取更符合用户需求的方案

---

#### 4.8.6 用户需求的特殊处理

如果用户明确提出关于交通规划的需求，需要特殊处理：

| 用户需求 | 处理策略 |
|----------|----------|
| 用户明确要求"详细规划交通" | 按详细规划执行，无论场景判断结果如何 |
| 用户明确要求"不要规划交通" | 按不规划执行，无论场景判断结果如何 |
| 用户未明确要求 | 按场景自动判断规划程度 |
| 用户反馈"交通信息太详细" | 降低规划程度（详细→简要，简要→不规划） |
| 用户反馈"交通信息不够" | 提高规划程度（不规划→简要，简要→详细） |

---

#### 4.8.7 规划程度的动态调整

规划程度不是一成不变的，可以在规划过程中动态调整：

| 调整触发条件 | 调整方向 | 说明 |
|--------------|----------|------|
| 用户反馈"交通信息太详细" | 降低规划程度 | 详细→简要→不规划 |
| 用户反馈"交通信息不够" | 提高规划程度 | 不规划→简要→详细 |
| 用户添加必去景点（交通不便） | 提高规划程度 | 交通不便的景点需要详细规划交通 |
| 目的地变更（从市中心改为郊区） | 提高规划程度 | 郊区景点交通更复杂，需要详细规划 |
| 出行方式变更（从自驾改为公共交通） | 提高规划程度 | 公共交通需要详细规划线路和时间 |
| 用户是首次到访 | 提高规划程度 | 首次到访需要更详细的交通指引 |
| 用户是重复到访 | 降低规划程度 | 重复到访不需要太详细的交通指引 |

## 6. 优化建议

### 6.1 当前规则的问题

1. **人群影响不明确**：当前人群参数对规划的影响点不清晰，影响比例不明确
2. **出行方式影响弱**：当前出行方式参数对规划的影响较弱，主要影响预算计算
3. **无上限参数收束不完善**：时间、人数、预算的兜底和收束规则不够完善
4. **景点间通行方式缺失**：当前规划没有景点间通行方式的建议

### 6.2 优化方向

1. **明确人群影响点和比例**：按照本文档设计，明确各人群对主要景点、辅助景点、节奏、餐饮、住宿、交通的影响点和比例
2. **增强出行方式影响**：按照本文档设计，增强出行方式对景点选择、景点顺序、每天景点数量、餐饮安排的影响
3. **完善无上限参数收束**：按照本文档设计，完善时间、人数、预算的兜底和收束规则
4. **增加景点间通行方式建议**：按照本文档设计，根据距离、人群、预算、特殊场景选择景点间通行方式，并在行程中给出建议
